# Blocks route (create)

Read before building a PDF from `blocks` or declaring form fields at `create`: a fillable form, a small document generated from data, or the fallback when no local browser exists.

## 1. The call
- Plan the reading purpose, type hierarchy, margins and page flow, then specify block styles directly. The writer supplies flow, not an art direction. `design.profile` explicitly opts into a preset; otherwise it does not redesign supplied blocks. Its default ink is a neutral one; `properties.palette` (below) sets the concept's colours for the blocks that carry colour. A representative page is optional when it resolves a real design uncertainty.
- `office action:'create' path:<file.pdf> format:'pdf' blocks:[...] fields:[...] properties:{ title, author, subject, keywords, pageSize:'a4'|'letter'|[w,h], orientation, margin, fontPath, pageNumbers, footer }`, then render and review before finalizing.

## 2. Blocks
- `{ type:'heading', text, level:1-3, size }`, `{ type:'paragraph', text, size, color, after }` (`\n` breaks a line; unspaced text wraps by character), `{ type:'list', items:[…], marker, ordered:true, indent }` (the marker is drawn with a hanging indent, so never type `• ` into a paragraph), `{ type:'table', rows, headers, columnWidths:[weights], columnAlignments:['left','right'], rowHeight, fontSize, headerFill, headerColor }` (the header row repeats after a page break; cells wrap and rows grow; without `columnAlignments` a column of figures — `₩2,400,000` and `$120` included — is set right and a label column — including `1호`, `2호` — stays left; the anatomy is the Word one: a bold header on a rule, hairlines between rows, no vertical rules, `grid:true` for the full cell grid; `headers:false` for a table with no header row, such as the totals under an invoice's lines — give that block the `x` and `width` of the figure columns it closes, so each total stands under its column rather than across the page from its label; `totalRow:true` sets the last row bold under a rule), `{ type:'image', path, width, height, align:'center'|'right' }` (PNG or JPEG; fits the text width unless sized), `{ type:'pagebreak' }`.
- The document anatomy beyond prose, each one block the writer flows the same on every page: `{ type:'cover', eyebrow, title, subtitle, meta:[…] }` (the title group of the first page — eyebrow in the accent, title, subtitle, meta lines, one rule under; the summary follows on the same page unless a `pagebreak` says otherwise), `{ type:'stats', items:[{ value, label }] }` (several figures with one cause on one baseline, equal columns, one rule under — at most four, and every value is a fact with a source), `{ type:'callout', label, text, fill }` (a tinted field with its label above the text: the conclusion, a warning, the ask; never split across pages), `{ type:'quote', text, attribution }` (someone else's words behind a rule in the accent, the attribution a caption under), `{ type:'chart', categories:[…], values:[…], chartType:'bar'|'column', unit, highlight, title, height }` (one series drawn by the page in the document's face: `bar` lays the bars across — a ranking, its names on the left — and `column` stands them up for periods left to right; every bar carries its value (`unit` follows the number: `'건'`, `'%'`), there is no grid, and `highlight` — an index or a category — takes the accent while the other bars recede; values are zero or more, one per category; a `caption` right after it travels with it), `{ type:'caption', text }` (the small muted line under a table, picture, or chart: what it shows and its source), `{ type:'rule' }` (a hairline between sections). Body copy leads at 1.5× its size so Hangul lines breathe; a heading keeps 1.2× and never ends a page. Which of these a document uses follows its genre: a decision report may open on a cover and a callout or stats strip, a letter or essay is headings and prose alone, a data log is a table with captions; a callout, quote, or closing ask appears only where the content has that job, and the order is not fixed.
- `properties.palette: { accent, muted, field, line }` (six-digit hex without `#`, all optional) overrides the writer's default ink for the cover eyebrow and rule, callout, quote rule, stats, chart bars, and table header and rules: `accent` the one emphasis colour, `muted` captions and labels, `field` the tinted callout and stat ground, `line` rules and hairlines. Take the four from the chosen concept's roles (`accent`, `muted`, `tint`, `line`).
- The block list is checked before anything is written: an unknown `type`, a block named with `kind`, an unknown field, or a missing `rows`/`items`/`text` is refused with every fault at once, instead of flowing as an empty paragraph. The writer flows and paginates; `pageNumbers` is on for multi-page output (`N / total`, bottom right) unless set `false`.

## 3. Form fields at create
- A form the reader fills travels with the copy that introduces it: `{ type:'field', name, label, fieldType:'text|checkbox|radio|dropdown|optionlist', height }` and `{ type:'fieldRow', items:[{ name, label, type }], gutter }` flow like any other block (a `checkbox` or `radio` is drawn as a square with its label beside it, a typed box with its label above; a `radio` with `options:[…]` is a question — its label above, the options in one row, each mark with its own words beside it; a `caption` right after a field block travels with its last row), so the writer fixes the page and the coordinates where the reader meets them, and a heading is never left on the page before its own boxes. Fields passed in `fields:[…]` keep the absolute `page`/`x`/`y` they were given, which is what stamping a form onto a scan needs.
- `fields:[…]` entries: `{ name, label, type:'text|checkbox|radio|dropdown|optionlist', page, x, y, width, height, value, options, multiline, maxLength, fontSize, labelSize, required, readOnly }` — a PDF field is a bare box, so `label` is the caption drawn above it (without one the page reaches the reader as unnamed rectangles), and the box may be written as `rect:[x, y, width, height]`; the layout is linted before writing — missing or duplicate names and out-of-page boxes fail, overlaps and boxes too small to use (under 24 × 12 pt typed, 8 × 8 pt marks) come back as `formIssues` on the result. A field that belongs with the copy around it is better declared as a `field` or `fieldRow` block, which flows with that copy instead of holding a page number the text may have moved off.

## 4. Fonts
The standard fonts cover Latin only. Korean, CJK, Cyrillic, or Greek text embeds a Unicode font found on the system (for example Malgun Gothic or Noto on Windows, Nanum/DejaVu/Noto on Linux); a PDF embeds what it drew with, so the reader needs no font. `properties.fontPath` chooses one, the result's `font.path` says which was used, and `action:'detect'` names it beforehand as `portable.pdfUnicodeFont`.
