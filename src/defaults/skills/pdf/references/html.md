# HTML route (PDF)

The default route for a new PDF: the model writes HTML/CSS for the content and intended reader, without selecting a preset, and passes it as `author`'s `script`. A local Chrome or Edge lays it out under the document's own `@page` rules, the runtime checks it, and the browser prints it — text stays text, headings become bookmarks, and the file is tagged. Inspect the printed pages for breaks, clipping, missing content, and readability before finalizing.

## 1. Two kinds of document
The HTML itself says which one it is: `<section class="slide">` pages make it designed pages (§2); anything else flows (§4-§8).
| | Designed pages (§2) | Flowing text (§4-§8) |
|---|---|---|
| For | one-pagers, brochures, certificates, handouts, proposals and reports composed as spreads — anything judged by its look and taken in page by page | contracts, manuals, letters, essays, and reports of running prose and tables |
| Pages | one `section.slide` per sheet, composed like a slide | the browser paginates the flow |
| Frame | the pptx skill's: brief, plan and facts gates, geometry gate, measured audit, receipt, scored critique | this file's checks and the per-page critique of SKILL.md |

**The route follows the page model, not a concept id**: designed pages when each sheet is a composed unit or a fixed page count is needed; flowing text when the content is read straight through and its length decides the page count. Either can be a report.

## 2. Designed pages — the deck's frame
Load the `pptx` skill and follow it as written for the brief (its §3 and `references/brief-critique.md`: `subject/audience/action`, `directions`, `style`, `facts`, `slide plan`), the workflow, `direction.md`, `composition.md`, `writing.md`, and its HTML route (`references/html.md`); the PDF differs only here:
**Hard rule — the canvas is the sheet**: `@page { size: A4; margin: 0 }` (any sheet of §4), and every `section.slide` exactly the sheet, written in its own units (`width: 210mm; height: 297mm`; 1 CSS px = 1/96 in, so A4 is 794 × 1123 px, A4 landscape 1123 × 794, letter 816 × 1056). The page margins are padding inside the slide. A margin on `@page`, or a slide of another size, is refused. → runtime `html_failed`
- **Type in pt**: here 1 px is 0.75 pt (the deck's canvas runs 0.5 pt per px), so take the pptx references' roles, not their px. A page is read in the hand, not projected: the `text` reading mode of `direction.md` §1, body 9.5–11 pt, captions 7.5–8.5 pt (the audit's print floors: body 9 pt, a one-line caption or note 7 pt, never the deck's screen 12 / 9 pt), page titles 20–32 pt, a hero numeral 60 pt and up; the plan's `hero` promise reads 40 pt+, `statement` 22 pt+. Margins 15–20 mm.
- **Charts are `data-chart`**, written exactly as the pptx HTML route's §5 (type, labels, values or series, colors, min/max, format, labelColor, size in pt, legend, grid, valueAxis, categoryAxis, gap, stacked, hole, plot): the deck frame reads it as a native chart (a plan line names it `chart`), and the runtime draws the same spec as an inline SVG on the page before it prints, value labels as text. A chart no spec covers (a dumbbell, an annotated line) is an inline `<svg>` drawn from the facts' values and named `picture` in the plan. `<table>` (`table`), `<img>`, and `data-icon` print as drawn.
- **Every page prints**: each `section.slide` goes on its own sheet and stays displayed in print (never hide the inactive ones in CSS); `aside.notes` is not printed. Pages that print onto more sheets than there are slides are refused.
- **No margin boxes**: with `margin: 0` there is nowhere for `@page` page numbers — set the folio and running head inside the slide, as the deck sets its page number, if the concept's chrome has them at all (a brand or statement page carries none). `h1`–`h3` still become bookmarks.
- **What comes back**: `designedPages: true`, the deck's `audit` (`status` pass/fail, top targets), `receipt` (with the printed pages' render readings), `render.contactSheet`, and `logs`; a later `render` on the session returns the receipt and contact sheet again, and `qa` adds the brief's readings (`plan_count_mismatch`, `fact_without_locator`). Refusals are the deck's: `html_failed`, `geometry_gate`, `plan_gate`, `facts_gate`. There is no `render.compare`: the PDF is the browser's own print.
- **Finalize** takes the pptx skill's scored critique (its `references/brief-critique.md` §3), one entry per page keyed `page` (or `slide`): `verdict`, the five scores, a page-specific `note`, `fixes`, `checks`; an anchor page carries `role`. An error the audit found holds finalize until the HTML is fixed and authored again.
- Copy that outgrows its page is split onto another page or cut (the deck's rule); content whose length should decide the page count is flowing text instead.

## 3. The call
`office action:'author' path:<file.pdf> script:<html> [overwrite:true] [properties:{ title, author, subject, keywords }] [render:false]`
- Returns `session`, `pageCount`, `printableArea` (CSS px), `warnings`, `facts` (flowing, §4), `htmlSource`, and unless `render:false` the rendered pages with `render.reviewToken`; designed pages add what §2 lists.
- Refusals land nothing; the target and any session on it stay as they were. `html_failed` — the browser could not run or the contract broke (the error names it, e.g. the missing `@page` size). `layout_gate` — `findings`, each with its `code`, the `element` (tag, class, first words), and the measure: `remote_image`, `image_missing`, `overflow_x`.
- Re-authoring the same path replaces the file and the session holding it; an existing file this runtime does not hold needs `overwrite:true`. The HTML is kept as `<file>.pdf.mixdog-source.html`. **Default — fix by editing that file**: change the lines that need it with the edit tool, then `author path:<file.pdf>` with no `script` re-authors from it (no `overwrite` needed); send the whole document again only when most of it changes.
- `<title>` becomes the PDF title; `properties` overrides it and sets author, subject, keywords.

## 4. Flowing text: document contract
**Hard rule — the sheet is declared**: the stylesheet opens with `@page { size: A4; margin: 18mm 20mm; }`. `size` is a named sheet (`A3`, `A4`, `A5`, `B4`, `B5`, `letter`, `legal`, `ledger`, each optionally `landscape`) or two lengths; margins in `mm`, `cm`, `in`, `pt`, or `px`. The margins frame the printable area every check measures against. → runtime `html_failed`
**Hard rule — pictures are local**: `<img src>` is a file beside the PDF (relative paths resolve from its folder) or a `data:` URI; a web URL is refused, and so is a picture that did not load. There is no network: no CDN fonts, scripts, or stylesheets. → runtime `layout_gate` (`remote_image`, `image_missing`)
**Hard rule — nothing wider than the page**: a table, a code block, a picture, or a row of cards wider than the printable width is cut at the margin by print. Give pictures `max-width: 100%`, let tables wrap their cells (`table-layout: fixed` with column widths in %), and wrap long code. A box inside a container with `overflow: hidden` is the container's business and is not reported. → runtime `layout_gate` (`overflow_x`)
- A full-bleed cover before a flowing body uses a named page: `@page cover { margin: 0 }` with `.cover { page: cover; break-after: page; }`.
**Default — the brief and its facts**: an optional `<!-- BRIEF` … `-->` comment at the top, one `key: value` per line (`subject/audience/action`, optionally `concept: <free text>` (`concepts.md` §1), `sources`, `facts: F1 2,400건 — 운영 시트 B4 · F2 …`). When it is present, every figure the printed pages show that no fact carries comes back in `facts` (`pages[].figures`); it is reported, not refused — answer it by adding the fact with its source or correcting the figure. `facts: sample — <why>` marks every figure illustrative, and the delivery says so. Dates, page counters, and small ordinals are not figures.

## 5. Flowing text: pages and breaks
- **Running head, foot, and page numbers** are a choice of the concept, and when present live in the `@page` margin boxes, never in the body. `counter(page)` works only there. Pick one variant (none is also right for a letter, a short document, or a statement piece), with the face and colour from the concept's roles:
  - running head top-right, folio bottom-right (a long filed report): `@page { @top-right { content: "분기 운영 보고서"; font: 8.5pt <face>; color: <muted>; } @bottom-right { content: counter(page) " / " counter(pages); font: 8.5pt <face>; color: <muted>; } }`
  - centred folio alone (a manual, an essay): `@page { @bottom-center { content: counter(page); font: 9pt <face>; color: <muted>; } }`
  - folio only on the inside edge, small (an editorial piece): `@page :left { @bottom-left { content: counter(page); … } } @page :right { @bottom-right { content: counter(page); … } }`
  - none: no margin boxes at all (a letter, a notice).
  Turn them off on a cover with `@page :first { @top-right { content: none } @bottom-right { content: none } }` (naming every box the document sets) or the named cover page.
- **Breaks**: `h1, h2, h3 { break-after: avoid; }` keeps a heading with what follows; `figure, table.compact, .callout, .card, tr { break-inside: avoid; }` keeps a unit whole; `p, li { orphans: 2; widows: 2; }`; `thead { display: table-header-group; }` repeats a long table's header on every page; `break-before: page` opens a chapter on a new sheet. A block that may not break but is taller than a page breaks anyway — the result warns `unbreakable_too_tall`; shorten it or let it break. A kept block that moves on leaves the page before it short: `qa` and finalize report a page before the last whose body stops above 70% of its height as `page_bottom_empty`, so keep only short units whole. A deliberate chapter or section break that leaves a page short is fine when the finalize critique says it is deliberate.
- **Backgrounds print**. A colour field or band behind a section prints as drawn; `position: fixed` repeats on every page, so use it only for a deliberate watermark or edge band.
- **Bookmarks** come from `h1`–`h3`: keep heading levels true to the structure (one `h1` for the title, `h2` per section), and never fake a heading with a styled `div`. A heading set on two lines with `<br>` keeps the space in its bookmark.
- **Not in the browser**: running heads taken from the content (`string-set`), table-of-contents page numbers (`target-counter()`), footnotes (`float: footnote`), and `leader()`. A contents list names the sections without page numbers (the bookmarks carry the navigation), and notes are endnotes.

## 6. Text and fonts (both kinds)
- Set `word-break: keep-all; overflow-wrap: break-word` on `body`, `text-wrap: pretty` on prose, `text-wrap: balance` on headings; wrap a name that must not break in `white-space: nowrap`.
- Faces: the browser embeds what it drew with, so the reader needs no font — but the face must be installed on this machine. Choose from the concept's menu (`concepts.md` §5): a sans (`'Noto Sans KR'`, `'Malgun Gothic'`), a serif (`'Noto Serif KR'`, `'Batang'`), or a serif-over-sans mix, with a Latin face named beside it. A face that is missing falls back silently: list the installed face first and a generic family last, and check the render.
- Sizes in `pt` or `mm` (the one document scale, shared with Word): body 10–11 pt with `line-height` 1.6–1.7 for Hangul, captions and running heads 8.5–9 pt, headings by a clear step (title ~24–32 pt, section ~15–18 pt, subsection 12–13 pt). Measure: 30–40 Hangul characters per line for body copy; a full-width A4 column runs long, so a report body often sits in a narrower column beside a side rail for captions or key figures.
- Contrast 4.5:1 for body text, 3:1 for 14 pt bold and up. A weight renders only if the face has it (Malgun Gothic has regular and bold; Noto families carry more); a missing weight is synthesized or rounded.

## 7. Tables, charts, pictures
- **Tables** are real `<table>` with `<thead>`; the treatment is the concept's — ruled (bold header on a rule, hairlines between rows), zebra (alternating `tint` rows, no rules), open (one rule under the header, wide rows), or a full grid (forms, parameter tables) — and no vertical rules unless the grid carries meaning; figures right-aligned with `font-variant-numeric: tabular-nums`, labels left; a total row set apart. The first listed is not a default. A caption under it says what it shows and its source.
- **Charts** are `data-chart` on an empty, sized element (the spec of §2), drawn by the runtime as SVG before printing; a chart no spec covers is an inline `<svg>` with numbers computed from one set of values (bar length = value / max × width), not typed separately. Either way: direct value labels, no gridline clutter, the subject's bar or point in the accent and the rest receding, the unit in the format (`"#,##0\"건\""`). JavaScript runs, but a chart library must be inlined, since nothing loads from the network.
- **Pictures**: `<img>` with `alt`, `max-width: 100%`, `object-fit` for a crop. A generated picture is mood or illustration, never evidence (figures, screenshots, and product UI are real or absent). Flowing text has no `data-icon`: draw icons as inline SVG (designed pages have it, §2).

## 8. Flowing text: design pass
Designed pages take the pptx skill's design pass instead. Before writing flowing HTML, plan once and check the plan against the defaults:
1. **Plan** from the subject and the sources, in the chosen concept (`concepts.md`): the palette roles (`paper`, `ink`, `muted`, `line`, `tint`, `accent`, optional `accent2`) as CSS custom properties; type roles in pt from the face menu; the grid (margins, column, side rail); the anatomy the genre calls for — a report may lead with its conclusion, an essay with its first paragraph, a letter with the sender block, a manual with contents. Emphasis carriers are a choice: a boxed note, a tinted band, a margin note, a left-rule quote, an oversized numeral, or no callout; the first listed is not a default. Write this document's stylesheet fresh.
2. **Check**: one anchor per page (the first thing the eye lands on is that page's claim); three tiers of space (inside a unit < between units < around sections); proximity carries relation (a label nearer its value than the next value); decoration never stands in for content. Avoid the generated look unless the brief asks for it: cream paper with a serif and a terracotta accent, an all-caps tracked label over every heading, identical rounded cards with one soft shadow, gradient washes, centred everything.

## 9. Review
`author` returns the rendered pages. Designed pages are reviewed as the pptx skill reviews a deck (§2). For flowing text, inspect every page for a heading left at a page foot, a table or figure split badly, a widow line, clipped or overlapping text, an empty trailing page, the margin boxes (numbers, running head) where they belong, and contrast. Fix in the HTML and author again; after two rounds on the same defect, keep the last valid file and report the residue. Then `finalize` with the per-page critique of SKILL.md.
