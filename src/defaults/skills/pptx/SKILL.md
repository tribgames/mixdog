# PPTX authoring (office tool + pptxgenjs)

The model designs; the runtime measures. Every slide is composed by the author from the kit's primitives — there is no slide type to pick and no function that draws a whole slide. The runtime checks what can be measured (fit, bounds, contrast, package validity, facts) and reports the rest as information the author weighs. This file owns the process, the brief contract, and the gate; every design decision lives in one reference. Pictures come from the `image` skill (`media`) or the user; the runtime has no photo library.

## 0. Route by task
| Task | Route | Done when |
|---|---|---|
| **New deck**, or a redesign the user wants rebuilt | one `author` script per deck (§2-§4); a new deck is never assembled from `batch` operations | `author` returns `audit.status: 'pass'`; `render` on that session returns the pages and a `reviewToken` |
| **Existing deck** — template fill, partial rewrite, reorder, merging decks | `open` → `snapshot` → `batch` slide and shape operations (§6); a new page is a duplicated source page, never a runtime-composed one | every `batch` returns its own `audit` for the edited slides |
| **Read or extract** — outline, text, or figures from a deck, or the material a deck is built from | `open` + a paged `snapshot` (`pages:[…]` or `cursor:`), or `node "${MIXDOG_SKILL_DIR}/scripts/source-extract.mjs" <file>` for blocks with citable locators | blocks prefixed `[slide 4]`, `[p3]`, `[Sheet1!B4]`, `[line 42]` |

Prerequisites: the Office capability (`metadata.requires`) — its portable backend needs no installed PowerPoint, and Office on Windows is used in the background when present; Noto fonts, provisioned with the capability; a signed-in `media` lane for generated pictures (none → a text-led cover, said in the summary); an explicit `--provider` and `--model` for the reviewer and page-QC scripts, which reuse the existing sign-in and never ask for credentials.

## 2. Workflow
1. Read the always-loaded references; add `charts.md` and `pictures.md` only on their triggers. Whether the cover — and so the deck — carries a picture is decided by `direction.md` §4 (a picture of the subject when a lane is signed in or the user supplied one; a text-led cover otherwise, recorded in the brief); when the cover goes without one because no lane is signed in or the user declined, the delivery summary says so. Done when the brief's mode, style, and picture decision can be written without guessing.
2. Ground: with source material, read it and write the fact sheet (each figure with its page or cell) before any outline; then the outline as assertion titles that read as one argument in sequence (`references/writing.md` for the sentence and notation rules). Done when every figure the outline will show has a fact line with a locator (§3).
   **Hard rule — copy is rewritten, never reinvented**: slide copy is condensed from the source in the deck's language with the source's own vocabulary; entity names, product names, figures, and abbreviations stay in their original form; a figure the source does not contain is not on the slide. → runtime `number_without_fact` for figures; wording → manual
3. Direct: define plausible directions, then compare two rendered compositions of the same representative content when the direction is open (`direction.md` §4; `references/review.md`). Select by reader understanding, not style names; a fixed template or small edit keeps its approved direction. The palette comes from a seed hue, the type from `typography()`. Done when the brief's `directions:` line names the candidates, the selection, and the visible reason.
4. Plan each slide before any geometry (`composition.md` §0): job, relationship, move, composition, carriers, texture, rhythm. Decide what the reader should understand from the visual itself; choose the relevant evidence or a faithful visual explanation before arranging the remaining copy. Content over the mode's budget is split or cut, never squeezed. Done when every slide has its plan line (§3).
5. Script: the brief (§3) as a comment block, then `deck({ hue, accentHue?, mode, script, pairing, fonts })`, then the slides. The runtime runs the kit — the code blocks of `kit.md`, `charts.md`, and `pictures.md` — before the script, so the script never pastes a helper (it may redefine one). Each slide is drawn spine → nodes → connectors → labels → garnish; every text box is measured (`MEASURE` through the kit helpers).
6. `office action:'author' path:<deck.pptx> script:<script>` (`overwrite:true` when re-authoring the same path) writes the file, opens the session, and returns three things:
   - **pages** — every slide rendered and one contact sheet of the whole deck (unless `render:false`);
   - **the composition receipt** — per slide: charts, tables, pictures, drawn shapes and their presets, fields, text boxes, background role, and `observe` (air, quadrant air, largest object share, visual footprint, text columns and stray boxes, fill areas, largest-type top, visual centroid and its offset from center, and after a render the pixel-read `renderAir`); `deck.rhythm` lists air, largest-type tops, centroid x, and render air in sequence;
   - **`audit`** — the measured read (fit, bounds, contrast, spacing, package faults) as `status` pass/fail, per-slide counts, the top targets, and the fix `round`.
   **Default — measure, then render the same session**: `author render:false` returns the receipt and the audit without pixels; `qa render:false` adds the design read (theme, plan promises, facts). When both are clean, `render` on that session returns page images, the contact sheet, the receipt, and `reviewToken` without rewriting the deck. Re-author only when the script changes; a repeated background author keeps the owned PowerPoint process and replaces its document. Measurements locate possible defects; they do not prove good line breaks, registration, or visual quality.
   **Hard rule — a failing audit is answered in the same turn**: fix every target the audit lists by re-authoring the script (or `batch` on the reported shapes), then read the `audit` that call returns; only `audit.status: 'pass'` counts as done. The runtime counts the rounds: after two failing fix rounds the residue is reported with the deck, never hidden by a third pass. → runtime `audit`
7. Open every persisted page image at readable size and inspect it against §5 and its intended message; the contact sheet checks sequence, not local alignment. For long decks returned as sheets, request pages in batches of at most 12 for detail. A promised comparison or explanation must be visible, not merely mentioned in a paragraph. Read the receipt as a diagnostic, not an object quota. Fix defects in the script; one or two loops is normal.
   **Hard rule — the loop converges**: each loop fixes every Hard hit and at most two Soft hits; a re-author that introduces a new Hard hit is reverted to the previous script; a defect that survives two loops is reported with the deck, not hidden by a third pass of taste edits. → manual
8. **Page QC (default for a new deck; skip for a one-page edit)**: after the measured audit, `qa render:false`, and the first render, hand each page to a fresh fixer session that sees only that slide — its rendered image, its element inventory, and its measured defects — with the office tool alone and a fix-only mandate (objective defects: overflow, clipping, collision, canvas edge, contrast, distortion; never redesign, reword, add, or delete). The fixer edits a working copy; the runner adopts it into the deck only when the page's measured defects did not grow and no other slide changed, and discards it otherwise. `close` the session first (the runner rewrites the file for every adopted page), then:
   ```text
   node "${MIXDOG_SKILL_DIR}/scripts/qc-pages.mjs" <deck.pptx> --provider <provider> --model <model> --output qc-report.json [--pages 1-12] [--no-vision]
   ```
   Provider and model are explicit, as for the reviewer; `--no-vision` runs the geometry read only (a text-only model, or no renderer); at most 20 pages per run. Read the report (`pages[].reason`: improved, polished as unchanged, clean, scope, regression, audit_failed, execution_failed), then `open` the deck again and `render` it: the QC edits invalidate the earlier `reviewToken`, and a reopened session no longer carries the brief, which is why the brief read (`qa render:false`) comes before this step.
9. Reader and art director pass — read the contact sheet for sequence and full-size pages for detail. For substantial new work, use the source questions and separate reviewer procedure in `references/review.md` (`node "${MIXDOG_SKILL_DIR}/scripts/review-deck.mjs" packet.json --provider <provider> --model <model> --output review.json`); with no fresh reviewer, explicitly label the pass self-review. Check the reader's answers against the original source key, then judge message visibility, focal hierarchy, and coherent variation before consulting `deck.rhythm`.
   **Output**: a slide-specific keep/fix decision with the visible reason. Resolve phrase-breaking wraps, weak evidence, and accidental empty regions; do not move a title merely to vary the sequence or change a successful page to reach a quota. Select at most two high-impact design revisions per pass; zero is valid.
   **Default — reuse the review**: small text, shape or data edits use `batch`, not re-author; every `batch` returns its own `audit` for the edited slides, read before the next edit. Portable renders report `changedPages` and `reusedPages` for up to 12 requested pages: inspect changed pages and carry forward the unchanged pages' critique. Shared resources invalidate the cache conservatively; PDF export remains whole-document. COM and long-deck contact sheets refresh normally. Always use the new complete render token, never the previous approval.
10. `office action:'finalize' session:<id> design:{ reviewed:true, reviewToken, critique:[...] }` — reuses a complete current preview, checks the document, saves, validates, and closes. Use the token from the final complete render; after detail-page inspection, restore a complete render before finalizing. An edit invalidates the previous approval. `fixes` lists work still owed; applied fixes belong in `note`. A render/export failure leaves the deliverable unfinished: preserve the session and artifacts, report the failure, and never substitute a manual save for successful finalize. Done when finalize reports the saved, validated file and the session is closed.

## 3. Brief (contract)
```
// BRIEF
// subject/audience/action: <what this deck must make someone do>
// reading mode: presentation | balanced | text · argument mode: pyramid | narrative | instructional | showcase | briefing
// directions: A <style, seed hue, pairing, motif — one-sentence note> · B <…> · selected: <A|B> · why: <visible reason from trial, or fixed-template constraint>
// style: <direction.md §3 id or custom> · palette: hue <deg> [· accent hue <deg>] · accent: <hex> · type: MODE <mode> → body <pt> · script: ko | ja | zh | latin · pairing: serif | weight | concord · fonts: noto | safe
// motif: <the selected style's device on anchors> · rhythm: anchor, dense, breathing, dense, ... , anchor
// sources: <file, document, or url the deck is built from> · <…>        (only when material was supplied)
// facts: F1 <value> — <source> · F2 <value> — <source> · ...        (or `sample — <why no source>` when every figure is illustrative)
// slide plan: 1 job: cover · move: <what the reader now holds> · composition: <the page move in words> · carriers: <…>
//   2 job: evidence · relationship: contrast · move: <…> · composition: <…> · carriers: chart, takeaway · texture: prose · rhythm: dense
//   ... N job: closing · move: <…> · composition: <…> · carriers: statement
```
**Default — the plan states intent**: every slide's plan line names its job, relationship, move, composition move, carriers, texture, and rhythm before any geometry exists, so the design is decided before it is drawn. The runtime reads the carriers back and reports, as information only, a slide that does not seem to carry what it named (`plan_promise_missing`) or a slide count that differs (`plan_count_mismatch`); neither blocks nor counts as a polish target. A thin request gets a defensible brief invented from the subject, never blank fields. The `facts:`, `directions:`, and `slide plan:` lines may wrap across comment lines; each continuation line is read as more ` · ` items — so ` · ` is the separator and never appears inside a value or a source (write "관측치와 측정", not "관측치·측정"; a fact cut at an inner ` · ` silently disappears and every figure it carried becomes `number_without_fact`).
**Hard rule — every figure has a fact**: `facts:` lists each number the deck will show, with its source (a page, a cell, a URL, or "user brief"). Dates and slide numbers are exempt. A chart series is one fact listing its values in order (`F3 운영비 1Q–6Q 10.5 10.8 9.1 7.9 7.0 6.5 — 재무팀 시트 B4:G4`); the values in the script's `chart()` call are copied from that line. With source material, the fact sheet is written first; without it, the facts come from the request and say so. **The runtime gates on it**: `author` reads the staged deck and refuses to land one that shows a figure no fact covers (`reason: facts_gate`, the figures listed per slide) — the previous deck and its session stay untouched, and the answer is the facts line, not a retry. A sketch or template with no source at all declares `facts: sample — <why>`: every figure is illustrative, the deck lands with `factsMode: 'sample'`, and the delivery tells the user the numbers are examples. → runtime `facts_gate` at author; `number_without_fact`, `facts_missing`, `facts_illustrative` in qa
**Hard rule — supplied material is cited**: when the deck is built from files or pages the user gave, `sources:` names them and every fact's source points where a reader can open it — a page (`p.12`), a cell (`Sheet1!B4`), a section (`§3`), or a URL. `node "${MIXDOG_SKILL_DIR}/scripts/source-extract.mjs" <file>` prints the material as blocks already prefixed with those locators, which is what the fact sheet quotes. A figure that came from somewhere else (a conversation, a live system) says so in its own source. → runtime `fact_without_locator` (advisory)

## 4. Script contract and library boundaries
- The kit prelude creates `pres` (`pptxgenjs`, `LAYOUT_WIDE` 13.33 × 7.5 in, coordinates in inches) and every helper; a script that declares its own `pres` runs without the prelude. Available modules: `pptxgenjs`, `sharp`, `node:fs`, `node:path`, `node:buffer`; no network and no photo library. Icons come from the injected `ICON` (256 offline Lucide stroke icons; `ICON.names` lists them, the kit's `icon()` / `iconRow()` place them) — a feature marker, a list prefix, or a stage glyph is an icon by name, never a Unicode emoji or a hand-drawn shape.
- End with `await pres.writeFile({ fileName: OUTPUT })` (OUTPUT is injected).
- Right after the brief: `deck({ hue, accentHue?, mode, script, pairing, fonts })` — the seed hue (the accent takes its counter hue unless the brief names `accentHue`; `accentHue: hue` is the single-hue deck), the reading mode, and the type line. `fonts: 'noto'` is the default for every deck (Noto is provisioned with the Office capability); `'safe'` only when the user says the recipients lack Noto. Charts go through `chart()` / `smallMultiples()` so the data stays editable; gradient fields, scrims, washes, and glows go through `gradient()` and the picture helpers so they stay native.
- `MEASURE(text, { font, size, bold, width, lineHeight })` is injected: it returns `{ lines, height, width }` in inches with the metrics the review uses; `lineHeight` is the box's `lineSpacingMultiple`. Every kit text helper sizes its box with it, pre-breaks Hangul by the eojeol (a word never splits across lines), and shrinks only along the type scale (`kit.md` §3); a free-form `addText` is sized with `fitH` too, never by guessing.
- Spread `RELATE({ id, role, label?, group?, row?, column? })` into shape options when meaning is known. Use slide-local unique IDs; a `value` names its `label` ID, and separate `table-cell` text shapes name their group, row and column. Roles also include `paragraph` and `object`. Native tables already encode cells. These declarations aid diagnostics, never waive fit, contrast or file validation; unknown relationships remain advisory.
- Leading, weights, and every position are the author's: the kit helpers default them and take `lh`, `font`, `bold`, `align` per box.
- Speaker notes: `slide.addNotes('...')`, never a text box.
- Pictures: user files (`{ path }`) through `picture()` or sharp-rasterized SVG (`{ data: 'image/png;base64,...' }`) at ≥ 2× the placed size in pixels.

The runtime absorbs what it can (one `a:pPr` per paragraph; package validation at finalize). What it cannot, the script must avoid:
| Boundary | Failure |
|---|---|
| A script that declares its own `pres` sets `pres.layout = 'LAYOUT_WIDE'` before its first slide (the prelude already does) | pptxgenjs defaults to 10 × 5.625 in and writes off-canvas coordinates without clamping → runtime `shape_out_of_bounds` |
| Colors are 6 hex digits without `#`; alpha via `transparency` (0-100, fills and images) or shadow `opacity` (0-1) — each is ignored on the other | alpha in the hex corrupts the file |
| A fresh options object for every add* call | the library rewrites option objects in place |
| Shadow `offset` ≥ 0; cast upward with `angle: 270` | negative offset corrupts the file |
| Shadows on shapes and text are `type: 'outer'` only | `'inner'` on a shape writes a mismatched closing tag and corrupts the file |
| `charSpacing`, not `letterSpacing` | ignored silently |
| Bullets: `bullet: true` on each item's first run, `breakLine: true` on every item but the last; `paraSpaceAfter`, not `lineSpacing`, between items | literal bullet characters and lineSpacing double the spacing |
| `rectRadius` only on `roundRect`; other corners are their own presets | ignored silently |
| Solid shape fills only; a gradient is a rasterized SVG image (`gradientField`) | gradient fill options are dropped |
| `margin: 0` when text must align with a shape edge | boxes carry internal padding |
| Stacked bar/column `dataLabelPosition` in `ctr`, `inEnd`, `inBase` | `outEnd` corrupts the file → runtime `chart_stacked_label_position` |
| A secondary-axis combo needs `valAxes` and `catAxes` with two entries each | PowerPoint drops the chart → runtime `chart_axis_undeclared` |

## 5. QA and finalize
**Content before pixels**: read the deck's text once against the fact sheet — `node "${MIXDOG_SKILL_DIR}/scripts/source-extract.mjs" <deck.pptx>` on the saved file, or the snapshot's `text` — for missing material, typos, and order; a wrong order or a dropped fact is cheaper to catch in text than on a contact sheet. → manual
Then inspect every rendered slide in this order. Read actual phrase endings, compare peer baselines and gaps, trace each connector to its intended boundary, and check that labels belong to the right object. Record a visible keep/fix reason rather than inferring a pass from a clean QA report. Hard hits need correction; the runtime's actual severity and source determine what blocks finalize. "Manual" means only the rendered image shows it.

Hard:
1. Out of bounds: any element past the 13.33 × 7.5 canvas. → `shape_out_of_bounds`, `content_touches_page_edge`
2. Overflow: text past its container or clipped at a box edge. → `text_overflow`, `text_clipped`, `text_box_too_narrow`
3. Text overlap: two text blocks intersect; text through a shape or line. → `shape_overlap` (text through a line → manual)
4. Readability: contrast below 4.5:1 (3:1 for ≥ 18 pt or bold ≥ 14 pt); text on a picture without a scrim. → `low_contrast`, `low_visual_contrast` (scrim presence → manual)
5. Collision: shapes overlap where z-order breaks the meaning. → `shape_overlap`
6. Broken picture: empty, stretched, or blurred raster. → `image_aspect_distorted` (empty or blurred → manual)
7. Missing element: leftover placeholder copy; a figure with no fact. → `placeholder_text`, `unfilled_token`, `number_without_fact`
8. System drift: a color outside the ladder, a face outside the safe list, a second saturated hue. → `accent_hue_overuse`, `font_family_overuse`, `theme_background_drift`, `unsafe_font_family`
9. Editability: a chart drawn from rectangles; a confirmed paragraph split into single-line boxes. → `dead_vector_chart`; `text_fragmentation` is an advisory candidate, not proof that independent labels should be merged.

Advisory (information the runtime reports; the author decides, never a polish target): monotony readings such as the same composition on most slides, one background throughout, or few visual roles (`repeated_layout_grammar`, `repeated_render_composition`, `flat_visual_rhythm`, `visual_role_variety_low`, `card_grid_overuse`), a canvas the reviewer reads as inactive (`under_composed_slide`, `slide_visual_density_low`, `meaningful_visual_missing`), and the plan read-back (`plan_promise_missing`, `plan_count_mismatch`, `art_direction_candidates_missing`). A deliberate composition overrides all of them; the receipt (§2 step 7) is where the author answers them.

Soft (fix when the change is local):
- Line step under 1.05× the font size, or a hollow gap over 1.5 in inside one block (breathing slides exempt). → `text_spacing_tight`, `vertical_imbalance`
- Same-column x or same-row baselines differing by more than 0.05 in; peer gaps differing by more than 5%. → manual
- The most prominent element is not what the slide is about. → `emphasis_mismatch`
- Caption more than 0.5 in from its picture; margins under 0.5 in; blocks closer than 0.3 in. → `stat_label_detached`, `edge_margin`, `shapes_too_close`

Finalize with `design: { reviewed: true, reviewToken, critique }`: reviewToken from the last render; critique holds one entry per slide with `slide`, `verdict` ('pass'), five 1-5 scores as top-level fields (`hierarchy`, `balance`, `legibility`, `cohesion`, `evidence`), a slide-specific `note` of 40+ characters, `fixes`, and `checks`. A score of 3 or lower on any axis, or any failed check, marks the slide as still needing polish. An anchor entry (cover, section, closing) carries `role: 'anchor'` (or its job name): its `evidence` score is recorded but does not gate, since a statement or a picture is the carrier there; the other four axes gate as usual.

**Hard rule — checks are the slide's own questions**: `checks` holds at least three `{ item, pass }` entries per slide, each a binary question written from that slide's plan line and facts before looking at the render ("the accent bar is Q4, the category the title names", "the 38 → 0 figures match F1 and F4", "the takeaway states a consequence, not a topic"), then answered against the render. Generic questions ("is the slide readable") do not count; a `pass: false` blocks finalize until the script is fixed. → runtime `visual_critique_incomplete`, `visual_critique_needs_polish`

Do not edit this skill or its references as a side effect of authoring a deck.
Report a repeated uncovered defect as a separate product improvement for
explicit review and approval.

Delivery distinguishes file validation from visual judgement: name the renderer actually used, which pages were inspected, and any unresolved defect. Do not claim to have inspected the live PowerPoint window when you read exported images. Deliver the editable deck and its persisted previews; an improvement request needs the improved result, not a large screenshot of the defective page with commentary unless a before/after analysis was requested.

## 6. Editing an existing deck (template fill, partial rewrite, reuse)
The source deck is the design authority and a slide library, not an outline. `open` it, `snapshot` the roster (a snapshot is paged — follow `pagination.nextCursor` with `cursor:` until `hasMore` is false, or ask for `pages:[…]`), `render` it once when the page structures must be picked by eye (the contact sheet is the layout gallery), and plan before any edit: output page → source slide → kept / edited / new copy, with one line of reason per edited or dropped page, and the content mapping (which material goes where; what is dropped because no page holds it). Pages from another deck come in through `import_slides` (`path`, `slides`, `after`); a token template (`{{name}}` in slides and notes) is filled with `fill_template` (`tokens`, `strict:true` to fail on an unfilled token); speaker notes are `set_notes`.
- **Structure before content**: `keep_slides`, `move_slide`, `duplicate_slide`, `delete_slide` first, then text and data edits; a page duplicated after editing clones the edits. After a structural batch the slides are renumbered to their new positions — re-`snapshot` before addressing `slide: n`. A kept page is never opened for writing — the validation baseline reports a changed master, layout, or theme part as `changed_protected_part`.
- **A duplicate shares its source's chart**: `duplicate_slide` copies the slide with its relationships, so both pages point at the same chart part and `set_chart_data` on either changes both. A copy that needs its own data gets `add_chart` (and `delete_shape` on the shared frame); pictures and tables are slide-local — `replace_image` writes a new media part, a table lives in the slide. → manual (compare both pages after the edit)
- **Units differ from the script**: the authoring script's pptxgenjs coordinates are inches, but a snapshot's shape bounds and every batch geometry field (`set_shape`, `add_shape`, `add_textbox` `left`/`top`/`width`/`height`) are points — 72 per inch, a 960 × 540 canvas for the wide layout. Convert before editing; a value copied from the script moves a shape to a corner.
- Portable snapshots expose stable `slideId` and `shapeId`; batch operations may use these instead of their positional indices. Do not reuse an ID from a different deck. For reversible edits, use `begin` before the batch, `diff` after it, and `rollback` if rejected; a failed mutation is never replayed automatically.
- **Match message to page structure**: a source page's layout already encodes a rhetorical shape (statement, lead-then-detail, comparison, progression, metric row); put each message on the page whose structure carries it, and drop the content or the page rather than force a fit. A new page copies the closest source page and empties its slide-local content.
- **Copy fits the slot, not the placeholder**: capacity comes from the box geometry and font size (`MEASURE`, `fit_text`), never from the old text's length. Overflow is resolved in this order: rewrite shorter → split onto another kept page → choose a larger source layout; shrinking type is last, and never deck-wide. → runtime `text_overflow`, `text_clipped`
- **Decoration was placed for the old text**: a template's underline, bracket, badge, or icon sits where the placeholder's line count put it; a replacement title that wraps to a second line runs through it. Inspect every edited page for it, then shorten the title or `set_shape` the decoration (points). → manual
- **Template slots ≠ source items**: fewer items than slots deletes the whole unused group (picture + text boxes), not just its text; more items than slots is a second page, never a smaller size. Placeholder wording never becomes content. → runtime `placeholder_text`, `unfilled_token`
- **Native data stays native**: `set_chart_data` / `set_table_data` edit the values, and `set_chart_series`, `set_chart_axis`, `set_chart_data_labels`, `set_chart_trendline`, `set_chart_error_bars` the rest; a chart is never replaced by a picture of one. Pictures go through `replace_image` into the existing frame, cropped to its ratio. → runtime `dead_vector_chart`, `image_aspect_distorted`
- **Finish the same way**: `qa` (with `autoFix:true` for fit repairs), `render`, inspect every edited page against §5, then `finalize` with the critique; the summary names which pages were kept untouched, edited, and added.
