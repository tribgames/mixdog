# Script route (pptxgenjs)

Read before authoring a pptxgenjs deck script. The HTML route never reads it.

## 1. Order of the script
The brief (`brief-critique.md` §1) as a comment block, then `deck({ style, hue, accentHue?, mode, script, pairing, fonts })` — the brief's style id is passed here, not only written down — then the slides. The runtime runs the kit — the code blocks of `kit.md`, `charts.md`, and `pictures.md` — before the script, so the script never pastes a helper (it may redefine one). Each slide is measured down before it is drawn — `const top = head(…)`, `avail(top)` for the height left, `shareDown(top, columnsH(…))` / `readingH()` when a row or rail shares it, then the carrier on the stage or column those give (`composition.md` §4 "measure down before drawing"; the helpers refuse under their floors and name the fix, so no y or h is guessed) — and drawn spine → nodes → connectors → labels → garnish; every text box is measured (`MEASURE` through the kit helpers).

## 2. Script contract
- The kit prelude creates `pres` (`pptxgenjs`, `LAYOUT_WIDE` 13.33 × 7.5 in, coordinates in inches) and every helper; a script that declares its own `pres` runs without the prelude. Available modules: `pptxgenjs`, `sharp`, `node:fs`, `node:path`, `node:buffer`; no network and no photo library. Icons come from the injected `ICON` (256 offline Lucide stroke icons; `ICON.names` lists them, the kit's `icon()` / `iconRow()` place them) — a feature marker, a list prefix, or a stage glyph is an icon by name, never a Unicode emoji or a hand-drawn shape.
- End with `await pres.writeFile({ fileName: OUTPUT })` (OUTPUT is injected).
- Right after the brief: `deck({ style, hue, accentHue?, mode, script, pairing, fonts, chrome?, theme? })` initializes palette, reading mode, type, and the frame. **`style` is the brief's `direction.md` §3 id, and it is mechanical**: it chooses the page chrome, the corner radius, the stroke a rule takes, the motif, the theme, and whether the accent stays on the seed hue — pass it, or every deck opens on the same page whatever its brief called the style. The chromes are `bare` (the title on the open canvas under its kicker, the source as one small line at the foot, the carrier filling the body at half the canvas — the page nine of ten reference decks draw), `bands` (a dark IR head band carrying the title and its `sub` line, Samsung-style; never a pale band on every page), `rail` (the title on the main column with the kicker in the left rail — editorial), `plane` (a full-height dark plane carrying the head, the carrier on the column beside it) and `masthead` (the title flush to the page top over one heavy full-bleed bar — brutalist); `chrome:` overrides the style's. The chrome sets `Z.body.x` and `Z.body.w`, so a carrier drawn at those never lands under a plane or outside a rail. `theme: 'dark'` is the Krafton deck — charcoal on every page, white type, one bright accent: the tokens swap once and every helper draws dark, so a dark deck is written exactly like a light one (the section field then takes `T.accentFill` with `T.accentLabel.color`, never the pale type-form accent under white). Before adding slides, adapt `T`, `TYPE`, or role definitions when the brand or composition needs it; the initializer is not a style lock. Use Noto by default or safe fonts for recipient compatibility. Charts stay native through `chart()` / `smallMultiples()` or native chart APIs; gradients use `gradient()` and the picture helpers.
- `MEASURE(text, { font, size, bold, width, lineHeight })` is injected: it returns `{ lines, height, width }` in inches with the metrics the review uses; `lineHeight` is the box's `lineSpacingMultiple`. Every kit text helper sizes its box with it, pre-breaks Hangul by the eojeol (a word never splits across lines), and shrinks only along the type scale (`kit.md` §3); a free-form `addText` is sized with `fitH` too, never by guessing.
- Spread `RELATE({ id, role, label?, group?, row?, column? })` into shape options when meaning is known. Use slide-local unique IDs; a `value` names its `label` ID, and separate `table-cell` text shapes name their group, row and column. Roles also include `paragraph` and `object`. Native tables already encode cells. These declarations aid diagnostics, never waive fit, contrast or file validation; unknown relationships remain advisory.
- Leading, weights, and every position are the author's: the kit helpers default them and take `lh`, `font`, `bold`, `align` per box.
- Speaker notes: `slide.addNotes('...')`, never a text box.
- Pictures: user files (`{ path }`) through `picture()` or sharp-rasterized SVG (`{ data: 'image/png;base64,...' }`) at ≥ 2× the placed size in pixels. Each one takes `alt` — one sentence on what it shows (`picture(s, path, x, y, w, h, { alt: '22시 3번 도크의 셔틀 적재' })`); without it the writer stores the file name, which describes nothing, and the audit reports `missing_alt_text`. `icon()` / `iconRow()` describe themselves (the icon name, or the item's label). An icon placed through `icon()` / `iconRow()`, and any SVG the script places with `vector(slide, svg, x, y, w, h)`, also ships its vector: the runtime attaches the SVG to the picture (result `vectorIcons`), so PowerPoint 2016+ draws it sharp at any zoom while older readers and the preview use the raster.

## 3. Library boundaries
The runtime absorbs what it can (one `a:pPr` per paragraph; package validation at finalize). What it cannot, the script must avoid:
| Boundary | Failure |
|---|---|
| A script that declares its own `pres` sets `pres.layout = 'LAYOUT_WIDE'` before its first slide (the prelude already does) | pptxgenjs defaults to 10 × 5.625 in and writes off-canvas coordinates without clamping → runtime `shape_out_of_bounds` |
| Colors are 6 hex digits without `#`; alpha via `transparency` (0-100, fills and images) or shadow `opacity` (0-1) — each is ignored on the other | alpha in the hex corrupts the file |
| A fresh options object for every add* call | the library rewrites option objects in place |
| Shadow `offset` ≥ 0; cast upward with `angle: 270` | negative offset corrupts the file |
| Shadows on shapes and text are `type: 'outer'` only | `'inner'` on a shape writes a mismatched closing tag and corrupts the file |
| `charSpacing`, not `letterSpacing` | ignored silently |
| Bullets: `bullet: true` on each item's first run, `breakLine: true` on every item but the last; `paraSpaceAfter`, not `lineSpacing`, between items | literal bullet characters and lineSpacing double the spacing |
| `rectRadius` only on `roundRect`; other corners are their own presets | ignored silently |
| Solid shape fills only; a gradient is drawn with the kit's `gradient()` (saved as a native `a:gradFill`; `gradientField` is its older name) | pptxgenjs gradient fill options are dropped |
| `margin: 0` when text must align with a shape edge | boxes carry internal padding |
| Stacked bar/column `dataLabelPosition` in `ctr`, `inEnd`, `inBase` | `outEnd` corrupts the file → runtime `chart_stacked_label_position` |
| A secondary-axis combo needs `valAxes` and `catAxes` with two entries each | PowerPoint drops the chart → runtime `chart_axis_undeclared` |
