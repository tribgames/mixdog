# Editing an existing deck (template fill, partial rewrite, reuse)

Read before the first edit of an existing deck. The source deck is the design authority and a slide library, not an outline.

## 1. Read and plan
A legacy `.ppt` is saved once as the `.pptx` beside it through LibreOffice when opened (`convertedFrom` names the original; an existing `.pptx` of that name is never overwritten). `open` it, `snapshot` the roster (a snapshot is paged — follow `pagination.nextCursor` with `cursor:` until `hasMore` is false, or ask for `pages:[…]`), `render` it once when the page structures must be picked by eye (the contact sheet is the layout gallery), and plan before any edit: output page → source slide → kept / edited / new copy, with one line of reason per edited or dropped page, and the content mapping (which material goes where; what is dropped because no page holds it). Pages from another deck come in through `import_slides` (`path`, `slides`, `after`) — the borrowed page brings the layout it was drawn on, which this deck's master adopts, so the two decks need not share a template; a token template (`{{name}}` in slides and notes) is filled with `fill_template` (`tokens`, `strict:true` to fail on an unfilled token); speaker notes are `set_notes`.

## 2. Operations
- **One batch of known operations**: every operation whose inputs are known goes in one `batch`; split only when a later input depends on an earlier result. `describe format:'pptx' operation:<op>` only when a field is unknown.
- **Structure before content**: `keep_slides`, `move_slide`, `duplicate_slide`, `delete_slide` first, then text and data edits; a page duplicated after editing clones the edits. After a structural batch the slides are renumbered to their new positions — re-`snapshot` before addressing `slide: n`. A kept page is never opened for writing — the validation baseline reports a changed master, layout, or theme part as `changed_protected_part` (a portable rewrite; when the Office application itself saved the file in background mode, its normalisation of those parts is reported as `applicationNormalizedParts`, not damage).
- **A duplicate owns its data**: `duplicate_slide` copies the chart and diagram parts the page owns (the result lists them as `ownParts`), so `set_chart_data` on the copy leaves the source page alone; pictures, themes, and layouts stay shared, and a table lives in the slide. A data refresh keeps the chart's treatment — labels, number format, series and point colors, the hidden axis and its zoomed range (`preserved` names what was carried). → runtime `set_chart_data` result
- **A hidden slide is withheld, not deleted**: the snapshot reports `slide.hidden`, and a page carrying it is skipped when the deck is presented. `set_slide_visibility slide: n visible: false` is how an appendix travels with its deck instead of being dropped or shown. A hidden slide owns no rendered page: the export skips it, so page numbers, the audit, and the critique cover the visible slides only. A shape hidden in the selection pane reads back as `shape.hidden`: it is neither measured by the audit nor read as the page's words.
- **A new page wears the deck**: `add_slide` without `layout` takes the layout of the slide it follows (its paper and chrome); boxes added to it copy the face, size, and `font.color` the snapshot reports for the matching box on a neighbour page (its title, kicker, source), and a native `add_chart` takes the deck's colours through `series[].color` — otherwise the page arrives in black type and default blue.
- **Units differ from the script**: the authoring script's pptxgenjs coordinates are inches, but a snapshot's shape bounds and every batch geometry field (`set_shape`, `add_shape`, `add_textbox` `left`/`top`/`width`/`height`) are points — 72 per inch, a 960 × 540 canvas for the wide layout. Convert before editing; a value copied from the script moves a shape to a corner.
- Portable snapshots expose stable `slideId` and `shapeId`; batch operations may use these instead of their positional indices. Do not reuse an ID from a different deck. For reversible edits, use `begin` before the batch, `diff` after it, and `rollback` if rejected; a failed mutation is never replayed automatically.

## 3. Content into pages
- **Match message to page structure**: a source page's layout already encodes a rhetorical shape (statement, lead-then-detail, comparison, progression, metric row); put each message on the page whose structure carries it, and drop the content or the page rather than force a fit. The snapshot reads that shape back on both backends: `slide.role` names the job the page does (`cover`, `comparison`, `process`, `metrics`, `split`, `statement`, `closing`, `content`) and `shape.slot` names what each box fills (`title`, `column-title-1`, `column-body-1`, `metric-value-2`, `step-title-3`, `chart`, `table`, `image`). A deck that was drawn rather than filled in carries no placeholder to answer with, so those roles are induced from the page's own geometry — the box in the loudest type is the title, a row of equally sized boxes is the columns, a figure above its caption is a metric — and one page reports one such structure, its strongest row. A new page copies the closest source page and empties its slide-local content.
- **One page from the template, filled**: `use_template_page` (`path`, `after`, and `role` or `slide`) brings that one page into the deck and writes its slots — `title`, `eyebrow`, `subtitle`, `body` (the lead prose), `source`, then `items[]` in order, each `{ title, body }` (a metric page reads them as `{ value, label }`). Among several pages of the same job it takes the one that holds the items with the least room left over; slots no item claimed are emptied, and more items than the page holds is refused, never shrunk. It expands to the import of that page and the writes into its own boxes, so it runs the same on both backends. Its chart, table, or picture still holds the template's data: the batch names each one in `templateData` (`slide`, `shape`, `replaceWith`), and each is replaced before the deck ships.
- **One bullet is `replace_text`, not `set_text`**: `set_text` replaces a shape's whole text with one paragraph in the formatting of the one that held its first text (as PowerPoint does), so a list box keeps a single line; change one item of a list with `replace_text`, and rebuild a list with `add_textbox` `paragraphs`.
- **Copy fits the slot, not the placeholder**: capacity comes from the box geometry and font size (`MEASURE`, `fit_text`), never from the old text's length. Overflow is resolved in this order: rewrite shorter → split onto another kept page → choose a larger source layout; shrinking type is last, and never deck-wide. → runtime `text_overflow`, `text_clipped`
- **Decoration was placed for the old text**: a template's underline, bracket, badge, or icon sits where the placeholder's line count put it; a replacement title that wraps to a second line runs through it. Inspect every edited page for it, then shorten the title or `set_shape` the decoration (points). → manual
- **Template slots ≠ source items**: fewer items than slots deletes the whole unused group (picture + text boxes), not just its text; more items than slots is a second page, never a smaller size. Placeholder wording never becomes content. → runtime `placeholder_text`, `unfilled_token`
- **Native data stays native**: `set_chart_data` / `set_table_data` edit the values (a row `set_table_data` adds repeats the last row's formatting, so retone a verdict or highlight it copied with `set_table_cell_style` — and values that grow above a total row leave a data row in the total's styling and the total in the added row: restyle both), and `set_chart_series`, `set_chart_axis`, `set_chart_data_labels`, `set_chart_trendline`, `set_chart_error_bars` the rest; a chart is never replaced by a picture of one, and the workbook behind it travels with the file. A template's horizontal bar chart usually reads bottom-up (PowerPoint's default; the result says `readingOrder:'bottomUp'`): categories with an order — months, ranks, steps — take `categoryOrder:'topDown'`, so they read from the top in the order given. Pictures go through `replace_image` into the existing frame, cropped to its ratio and carrying enough pixels for the frame; pass `altText` with it, or the frame keeps describing the picture that just left it. → runtime `dead_vector_chart`, `chart_data_unlinked`, `image_aspect_distorted`, `image_low_resolution`
