# Migration security review list

Task `x-sec-checklist` (G1). Every boundary the migration moves or keeps, with its code site, the task that owns
it and the test that guards it. The reviewer fills the `status` column per wave; it starts empty.

Rules this list is held to (owner direction): a boundary is reviewed for what it enforces today, and no row adds a
prompt, confirmation, setting or refusal that the old main process did not have. Where a row says "parity", the
guard is that the Rust path answers what main answered, not that it refuses more.

Sites were re-checked in the integration tree at `mig/int` (base `6dcf44bc47`). `file:line` is where the symbol
sits at that commit; line numbers drift, the symbol is the anchor. A site marked `(new)` does not exist yet and
is named by the task that creates it. A test marked `manual` is run by the owner or the reviewer by hand.

Abbreviations: Core = `native/core/crates`, Desk = `apps/desktop/src`.
