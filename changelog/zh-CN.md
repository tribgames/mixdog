## v1.4.3 - 2026-10-31

新增工作树设置与分支清理功能，将会话目标任务重构为待办事项列表，并引入可自定义的输入框样式。

### 新功能

- **工作树设置** — 新增 设置 → 工作树 页面，提供磁盘占用统计、打开与删除操作，以及超过 15 个工作树或闲置 30 天后的自动清理规则。
- **分支菜单工作树操作** — 在分支菜单底部新增 新建分支、新建工作树 和 清理 操作，支持搜索高亮；无可安全删除的项时清理操作保持禁用。
- **会话待办事项列表** — 新增替代目标任务的会话待办列表，实时显示代理进度，并在会话关闭后保留最后的待办项与目标。
- **输入框样式** — 在设置中新增 简洁、标准 和 详细 输入框样式，支持实时预览、响应式工具栏以及可选的回答确认步骤 (#270, #276)。
- **委派设置** — 新增独立的 设置 → 委派 页面用于配置编排指令，并支持在输出样式中直接编辑指令及重置为默认值 (#291)。
- **例程执行子代理** — 支持为定时任务和 Webhook 指定使用独立模型的执行子代理。
- **导入 Claude Desktop Cowork** — 支持导入 Claude Desktop Cowork 对话记录，星标对话排在最前 (#283)。
- **聊天中的路径链接** — 支持在聊天中点击打开电脑上的任意路径：文件夹在文件面板中作为新根目录打开，可预览文件在 Visualize 中打开 (#277)。
- **手机端图片手势** — 在手机端聊天与 Visualize 中支持双指捏合缩放、平移以及双击缩放图片 (#275)。
- **Fast 调用用量统计** — 为模型的 Fast 调用增加独立的用量明细行，并适配手机端用量表格显示 (#288)。
- **会话生命周期自动化** — 在空闲期间自动归档闲置满 7 天的会话，并自动清理已归档满 90 天的会话。
- **电脑使用中暂停手机通知** — 当正在主动使用本台电脑时，自动暂停向手机推送通知。

### 变更

- 工具活动行现将重复操作合并为带计数的标签与任务名称，例如“工作树管理 ×4”。
- 在任何位置修改的设置与指令均在下一轮次直接生效，无需重启会话，也不会破坏提示词缓存。
- 网页搜索改为直接加载，省去延迟工具调用的中间步骤，加快查询速度。
- 手机端远程浏览器滑动关闭手势现仅限制在左侧边缘条触发，避免在操作网页时误触关闭。
- 输入框中的代理 Token 用量读数现会在每次模型调用后约 1 秒内刷新。
- 空闲垃圾回收现会一并清理外部缓冲区内存，降低守护进程内存占用。
- 将目标的执行时限改为仅作为上限；代理在验证工作完成后即自动结束而不再占满整个周期，并移除了 `--time-mode`。

### 错误修复

- 通过持久轮次移交与检查点恢复机制，修复了崩溃或重启后未保存轮次丢失的问题。
- 修复了拖拽选中文本后松开鼠标导致桌面端渲染进程崩溃的问题。
- 通过保持最近对话挂载，修复了切换会话时重新构建记录或重复播放动画的问题。
- 修复了停滞的目标将空闲时间计入预算、重复发送通知或未经确认覆盖已有目标的问题。
- 通过请求刷新令牌修复了连接器登录在 1 小时后过期的问题，并避免在重用已删除账号名时发生账号混淆 (#285)。
- 修复了 Windows 上更新插件重命名文件夹时因 `EPERM` 文件锁定错误而失败的问题 (#284)。
- 修复了嵌入清理期间移除了 onnxruntime-node 脚本导致安装失败的问题 (#282)。
- 修复了进程异常退出后因残留 PostgreSQL 锁导致内存服务启动卡死的问题 (#278)。
- 通过授予 Chrome 兼容的存储访问权限，修复了内置浏览器中 reCAPTCHA 及认证小部件无法工作的问题。
- 修复了子代理报告因提醒、排队输入或后续错误被打断而未能送达 Lead 代理的问题。
- 修复了 Computer Use 在屏幕读取缓慢时重启输入宿主，以及在短暂输入间隔中误报观察器损坏的问题。
- 修复了记忆搜索在多语言混合查询中丢失韩文内容词的问题，并优化了精确词扫描逻辑。
- 修复了配对手机上的网页链接和推流浏览器标签页未能适配移动端屏幕或未在 Visualize 中打开的问题。
- 修复了狭窄窗口下设置颜色行与描述文字重叠的问题，并防止并发修改指令时发生覆盖 (#287)。
- 修复了在工作树内运行 `npm ci` 会清空主检出目录中的 `node_modules` 的问题；现在每个工作树都会安装自己独立的依赖项。
- 修复了重新发送启动失败的任务（例如在不支持工作树的文件夹中）会持续重复提示“could not be resumed”直至重启的问题 (#279)。
- 修复了在 Windows 上因会话临时文件夹路径过长导致 Git 和 Office 文档工具运行失败的问题。
- 修复了 Vertex AI 的 Gemini 4 Argon 和 Gemini 3.8 Flash 模型缺少推理强度控制选项的问题；现在会显示选择项（Low、Medium、High），并且所选级别会随请求一同发送 (#292)。

## v1.4.2 - 2026-10-29

改进了代理调度框架：新增专门用于代码探索的 Explore 代理与强化验证的 Test Suite 技能，并支持 Vertex AI 以及单个连接器绑定多个账号。

### 新功能

- **Explore** — 新增可选的只读探索代理，Lead 可以一次向它委派多个代码问题；可在 工作流 → 内置代理 中为其选择模型。
- **Test Suite 技能** — 新增用于编写、运行、排查和精简项目测试的内置技能。
- **Vertex AI** — 新增 Vertex AI 支持，可使用 Gemini、Claude 及开源模型，支持通过服务账号密钥、gcloud 登录或 Express 模式 API 密钥登录 (#249)。
- **连接器多账号** — 单个连接器支持绑定多个账号；未指定账号时，代理默认使用上次用过的账号。
- **自定义提供商密钥与请求头** — 支持配置多个 API 密钥以便在额度用尽时自动接替，并支持为每次请求附加自定义 HTTP 请求头 (#233, #239)。
- **机器人的连接器工具权限** — 在机器人配置中，支持按连接器的每个工具分别设置 自动、需要批准 或 已禁用 (#264)。
- **在屏幕机器人气泡中审批** — 屏幕机器人的对话气泡中直接显示审批请求以及 允许 和 拒绝 按钮。
- **一键停止所有后台命令** — 新增 `/stop` 命令以停止当前会话的所有后台命令，桌面端现也支持 `/shells` 和 `/mcp login`。

### 变更

- 检查失败时，代理会去修复根本原因，而不是反复重试、调高超时或直接跳过。
- 机器人的定时签到与提示词缓存预热默认改为关闭。
- 桌面端与 CLI 现遵循系统代理设置，桌面端会按地址应用 PAC 脚本与例外规则，同时保持本地与局域网（LAN）地址直连。
- 工具活动行仅在命令仍在运行时显示已用时间。
- 代理因被判定为无进展而停止时，会在 `history/tool-failures.jsonl` 中记录一条 `stall_abort` 行，以便在代理被误停时进行反馈。
- Windows 上的 Git 改为直接启动 `git.exe`，并减少记录轮次变更时启动的进程数，从而加快对话轮次、撤销/重新应用以及 git 工具调用的速度。

### 错误修复

- 修复了 Windows 上停止命令的相关问题：点击 停止、仍然释放、超时或关闭会话后子进程仍在继续运行，停止后台命令时可能卡死，以及将无关的旧进程误判为残留进程 (#259)。现在每条命令都在独立的 Windows 作业（Job）中运行；设置 `MIXDOG_SHELL_ALLOW_BREAKAWAY=1` 可允许命令在作业外部启动进程。
- 修复了群聊在额度用尽时每个机器人都重复提示“未能回复”的问题；现在只会停下一次并说明原因。
- 修复了会话视图的多项问题：长会话或已压缩会话无法向上滚动回第一条消息、其他会话发送大型更新时显示“会话不可用”，以及手机端“会话”抽屉打开的是“机器人”页面而非聊天界面。
- 修复了仅以压缩文件保存的 Codex 对话无法导入的问题 (#262)。
- 修复了服务端丢失 Mixdog 注册信息后，连接器登录反复报错 "Unrecognized client_id" 的问题 (#269)。
- 修复了 TUI 中过长的登录 URL 被截断的问题，并新增 `Ctrl+Y` 快捷键用于复制链接 (#261)。
- 修复了高负载 Windows 电脑上语音输入无法启动，以及设置或会话保存失败的问题。
- 修复了包含中、日文内容的表格单元格撑破表格边框的问题。
- 修复了 Vertex AI 模型缺少服务层级（Standard、Flex、Priority）选项，以及排队中的 Flex 请求在一分钟后被断开的问题 (#271)。
- 修复了单次进度读取失败导致活动计时器停止更新，进而误判代理无进展并将其停止的问题。
- 修复了 Computer Use 的 `verify` 无视 `timeout_ms` 在 2 秒后即放弃检查，以及在无法读取管理员权限窗口文本时无谓等待的问题 (#274)。

## v1.4.1 - 2026-10-27

修复了通过 SSH 登录、PC 访问权限设置失败以及代理在 Anthropic 模型上停止运行的问题，并为并排显示的 Visualize 标签页添加了视图切换功能。

### 新功能

- **无浏览器登录** — 为 ChatGPT 和 Grok 添加了设备代码登录功能，在通过 SSH 连接或无显示器时在 TUI 面板中显示登录 URL 或验证码 (#242)。
- **Visualize 视图切换** — 在并排显示的 Visualize 标签页缩放胶囊中添加了视图切换功能，可同时显示两个窗格或一次仅显示一个窗格。
- **从聊天直接安装 APK** — 添加了直接在 Android 软件包安装程序中打开已下载的 APK 而非通过分享面板打开的功能 (#241)。

### 变更

- 调整了机器人机制，在向其他机器人发送消息、读取或检查时通过其 bot id 进行寻址。
- 调整了侧边栏、未读小圆点和代理启动机制，在会话列表较长时具备更快的响应速度。

### 错误修复

- 修复了在驱动器根目录带有仅继承权限的 PC 上设置 PC 访问权限失败的问题，并展示了审批未能完成的原因 (#251)。
- 修复了 Anthropic 模型上的代理在思考或写入大文件时被判定为停滞并中断的问题 (#248)。
- 修复了自定义 Responses 路由上的代理在首次输出前被判定为停滞的问题 (#244)。
- 修复了在部分 PC 上 Computer Use、Browser Use 以及登录回调报错 "bad port" 失败的问题。
- 修复了在备用模型所属提供商中选择主模型时报错 "duplicate route provider" 失败的问题。
- 修复了自动切换至备用模型时一次性发送所有 MCP 工具的问题。
- 修复了导入的 Claude 和 Codex 对话丢失早期历史记录、标题或分页的问题，并将它们的工具使用记录显示为折叠的活动行 (#245)。
- 修复了孤立的 worktree 残留以及默认分支被纳入托管 worktree 的问题 (#247)。
- 修复了委派工作结束后机器人仍显示为工作中以及压缩会话缺少完成圆点的问题。
- 修复了在请求中断或重启后提示词缓存被重新构建的问题。
- 修复了位于回复末尾的表格或代码块丢失底边框以及手机狭窄屏幕上表格单元格间距丢失的问题。

## v1.4.0 - 2026-10-27

改进了结合 Browser Use 和 Computer Use 的手机端远程工作体验，并精简了代理框架以跳过冗余检查、更快完成工作。

### 新功能

- **远程 PC 屏幕** — 添加了通过直接 WebRTC 连接从手机查看和控制 PC 屏幕的功能，配备特殊按键以及 PC 端状态胶囊。
- **PC 访问权限** — 添加了从手机访问管理员提示、锁定屏幕和 `Ctrl`+`Alt`+`Del` 的可选权限，只需在 Computer Use 设置中或使用 Windows 密码批准一次即可。
- **浏览器实时视图** — 添加了通过 WebRTC 将应用内浏览器串流至手机的功能，使接管页面适配屏幕，并支持使用手机键盘直接打字。
- **通知控制** — 在设置 → 通知下添加了按设备设置通知、对话静音、免打扰时间段以及错误通知功能，并在审批通知中加入了允许按钮 (#221, thanks @dislight1123)。
- **机器人委派工作** — 在回复下方为机器人委派的工作按任务实时显示单行进度，展示执行进度并允许在聊天中直接回答问题。
- **已保存的登录信息** — 添加了使用在设置 → 认证管理下管理的已保存登录名和一次性验证码自动登录的功能，模型绝不会接触机密数据。
- **导入 Chrome 登录信息** — 添加了将 Chrome 保存的登录信息（包括较新的绑定应用的加密凭据）导入全新登录页面的功能，并带有保存/保持登录开关。
- **通过邮件登录** — 添加了打开登录链接并从已验证邮箱中自动填写验证码的功能，并记住每个网站所使用的身份提供商。
- **在 Chrome 和 Edge 中使用保存的登录** — 添加了 Computer Use 将保存的登录信息填入您自己的 Chrome 或 Edge 中的功能，且不向模型泄露凭据。
- **提示词缓存预热** — 在设置 → 上下文下为 Anthropic 模型添加了提示词缓存自动预热功能，可学习您的返回习惯并在计划运行前提前预热机器人。
- **更多 Google 连接** — 添加了将更多 Google 账号连接至 Gmail、Calendar 和 Drive 的功能，支持针对每次请求选择账号并提供清晰的登录提示。

### 变更

- 调整了代理的执行逻辑，使其在所有编辑完成后仅验证一次而非在任务中途验证，并行运行相互独立的工具调用，并保持简短的进度更新。
- 将设置重构为四个板块：基本、AI 行为、集成和支持。
- 调整了会话菜单，允许用户自定义侧边栏所显示的板块。
- 调整了打字、会话与标签页切换、搜索、设置、侧边面板、终端以及变更界面的响应，使其瞬间打开，并具备更流畅的状态动画。
- 调整了机器人委派会话的审批机制，使其显示在等待该审批的每个对话中，并在每张审批卡片上保持相同的文案与按键。
- 调整了会话和机器人行，在等待审批时显示琥珀色三角形，遇到提问时显示问号图标，并展示待处理工作数量。
- 调整了机器人任务会话和子代理，使其带有独立的未读小圆点，并随汇报目标对话一起标记为已读。
- 调整了已配对手机的处理方式，使其能像 PC 端一样读取、预览、下载和打开文件。
- 调整了 `@` 文件选择器，优先列出层级较浅的路径，默认展示近期工作，并能在关联文件夹中查找文件 (#228, thanks @reeves-ai-lch)。
- 调整了 Visualize，使其可从任意本地文件夹打开页面，并以所属文件夹命名索引页面。
- 调整了用量弹窗和已固定的用量指示条，在全宽进度条上方单行显示各项额度限制。
- 调整了 shell 工具，使其支持可选的工作目录，并拒绝 2 秒或更长时间的 sleep。
- 调整了代理终端运行和浏览器页面，使其在 PC 及配对设备上显现相应标签页，并支持直接从记录行中打开。
- 调整了 Browser Use，限制每个会话的后台页面数量，并在单轮交互结束后将其关闭。
- 调整了重试等待界面，显示固定的原因和实时倒计时，而非原始错误文本。
- 调整了机器人对话界面，回复下方不再显示变更文件卡片，分隔较远的消息，且移交任务信息与时间共享单行展示。
- 调整了语言列表，将韩语以其母语名称显示。
- 调整了 Mixy 的定期检查机制，默认每小时运行一次，可在设置 → 机器人中自定义间隔。
- 调整了手机应用，使其在网络允许时直接连接到 PC，并自动回退到中继。
- 调整了侧边面板使其共享同一宽度，可在 280 到 1160 像素之间调整。
- 调整了手机端侧边浮窗，支持在抽屉层任意位置滑动以关闭，并使抽屉行与文本微光动画更加流畅。

### 错误修复

- 修复了应用本地存储重置时分栏布局丢失的问题。
- 修复了侧边面板打开或关闭时面板边缘、分割线及颜色发生偏移的问题。
- 修复了手机抽屉在滑动关闭过程中内容提前消失的问题。
- 修复了侧边面板关闭后固定机器人偏离输入框右端以及进入对话时内容下移一行的问题。
- 修复了机器人的任务会话运行时其所在行未转动或未显示未读小圆点的问题。
- 修复了点击桌面通知后侧边栏停留在上一会话或窗口隐藏时无反应的问题。
- 修复了回答对话末尾的问题卡片后记录未能跟随新回复滚动的问题。
- 修复了使用明确指定模型创建的任务会话报错 "service is not defined" 的问题。

- 打开了标签页的点击不再被报告为什么都没做的点击。`target="_blank"` 链接不会改动当前文档，因此回复曾回答“No observable change”并让调用者去找遮挡元素——而它刚刚打开的页面就在 `list_tabs` 里，却未被提及。回复现在会指明打开的页面以及如何对其操作。

- `drag` 像其他所有指针操作一样支持无需快照的目标。它的两端过去只接受 ref 或原始坐标，而页面中可拖动的元素——卡片、列表行、放置区——往往没有可访问名称，因此也没有 ref，所以即使已知 CSS 选择器，移动一个元素也得先对视觉快照进行定位。现在 `target` 和 `dropTarget` 用来指明两端，并在一次观察中一起解析；ref 和坐标的用法与之前相同，两端仍必须用相同的方式寻址。

- 保存的文件不再被通报为失败的请求。变成下载的地址会取消自身的导航，Chromium 将该取消报告为 `net::ERR_ABORTED`，因此列出了该下载的回复也把它列为近期的网络故障。被取消的请求——下载、页面放弃的 fetch、被另一个导航取代的导航——仍可通过 `network` 查看，但不再被主动当作页面的故障报告；真正失败的请求仍会如此。

- `brief` 回复不再把一个被填写的字段变成整页的变化。它与调用者上一次的观察进行比较，而当那次观察被截断或过滤时，它从未报告过页面的其余部分——于是其外的每个元素都被列为“changed or new”。在表单中填写三个框会返回十五个元素，输入一个搜索词则返回一百四十六个。回复现在会把该操作确实改变的内容与先前观察根本没有覆盖的内容分开，并说明那次观察涵盖了页面的多少。无论哪种情况都不会省略任何内容。

- `network` 中的请求头就是实际发送的那些。Chromium 先报告一组临时的请求头，之后再补充语言、编码、客户端提示和 cookie，因此请求详情可能只显示两个请求头，读起来就像页面从未请求韩文内容。现在会合并后一组；凭据仍只列名称而从不显示。请求头名称不区分大小写，而两次报告的拼写不同，因此合并时每个请求头只保留一条——实际发送的拼写和值——而不是把 `User-Agent` 和 `user-agent` 当成请求携带了两者而分别列出。

- 站点现在看到的浏览器使用就是渲染它们的那个 Chrome 版本。此前 user agent 字符串仍带有桌面应用版本和 Electron 运行时，而同一页面收到的客户端提示却只提到 Chromium；GitHub 对这一矛盾的回应是在公开仓库上设置登录墙。浏览器分区现在提供纯粹的 Chrome 字符串——少了一个指纹，也少了一些“不支持的浏览器”的弯路——并且当任务要求模拟 user agent 时，模拟的 user agent 仍然优先。

- 持续附加框架的页面现在可以再次被观察。门户网站和新闻首页会成批地打开广告位和小组件，而在批次中途开始的快照过去会以“frame topology changed during observation”放弃——第一次和第二次尝试都能稳定复现。观察没有副作用，因此收集器现在会短暂等待批次稳定后再次读取，直到一个很小的上限，而不是为一个只是繁忙的页面向调用者抛出错误。当读取仍然失败时，回复现在会说明页面已加载、只是读取失败，因此下一步应当再次观察，而不是放弃一个完好的页面。

- 页面只报告它自己的故障。上一个文档的请求和控制台错误曾留在台账中，因此对一个正常页面的快照可能列出此前访问的站点的被中止请求，干净页面上的 `console` 也可能回答上一个页面的错误——两者都让读者去追查并不存在的故障。加载新文档会清除它们；在同一文档内导航则保留它们，因为没有重新加载。

- 浏览器使用中的显示竞态不再算作失败。与导航或窗口大小调整竞争而失败的捕获，现在以重新采样标记作答而不是错误，因为窗格本来就会再次请求页面接下来显示的内容。正常浏览过去会让应用日志充满捕获失败——一次测试运行中有十七条，现在为零——已配对的手机则把同样的竞态报告为“could not connect to browser screen”；现在它按活跃节奏重新采样，只报告确实停止推进的显示。

- 可以清除浏览器使用的浏览数据。浏览器窗格有一个橡皮擦按钮，可移除缓存、站点存储在本设备上的数据和 cookie，每一项都是独立的选择：缓存默认选中，因为丢失它只意味着一次较慢的重新加载，而 cookie 会让你退出所有站点的登录，因此绝不会是默认值。每个范围独立清除，因此一次失败会被报告为失败，而不会消失在成功的范围背后。清除 cookie 还会改写在重启之间保存会话登录的加密文件，这样你清除的登录在应用下次打开时不会回来——如果该文件无法改写，cookie 会被报告为未清除，而不是已完成。在此之前，共享分区在磁盘上不断增长，却没有办法回收。

- 浏览器使用的 `performance` 指标现在报告绘制页面的进程的内存，而不仅仅是 JavaScript 堆：图片和图层占用大量内存的页面过去看起来很小。读数会指明该进程，因为一个渲染器可能绘制同一站点的多个页面。

- 浏览器使用的域名策略涵盖对等连接。当运营者限制页面可以访问的域名时，WebRTC 不再通过 STUN 和 TURN 绕过过滤：页面及每个子框架中的对等连接都会被拒绝。没有域名策略时没有任何变化，而且这仍然是对页面代码的约束，而非网络边界。

- 浏览器使用的元素截图。`snapshot mode=visual` 接受 `ref` 或 `target`，并将该元素作为独立图像返回。边框以顶层文档的 CSS 像素测量——同进程框架在页面一侧折算其偏移，跨源框架加上其会话偏移，但不进行保护输入的命中测试，因为图片不派发任何事件，而处于 CSS 变换下的框架同样值得一张图片——并且裁剪按图像与视口之比缩放，因此在缩放或高 DPI 显示器上同样成立。比窗口更高或更宽的元素会从文档捕获而非视口中裁出，因此长表格或文章会完整呈现，而不是止于折叠线；只有过大而无法捕获的页面才会退回到可见部分，并会如实说明。该图像仅供检查：它绝不会被绑定为坐标定位，因为对元素执行操作仍应使用 ref。`mode=semantic`、`fullPage` 和 `format=pdf` 会拒绝 target，而不是忽略它。

- 浏览器使用的输入保真度。`drag` 现在可以完成页面自己的 HTML5 拖放：Chromium 的拖动拦截会交出页面发起的载荷，手势以 `dragEnter`/`dragOver`/`drop` 结束，这正是看板卡片、可排序列表或文件放置区实际监听的事件；只跟踪鼠标事件的页面保持之前的路径。`type` 为每个字符发送真实的按键事件，而不是插入整个字符串，因此由按键驱动的自动补全和组合框会有所反应，而美式键盘布局之外的字符（韩文、emoji）仍以文本插入。`press` 为标点发送美式键码（`.` 过去是 Delete，`-` 过去是 Insert），避免快捷键输入字符，并且不再根据大写字母推断 Shift，这曾把 `Control+A` 变成 `Control+Shift+A`。`upload` 可将文件放到从不打开文件选择器的元素上，并带有一个中和未处理放置的保护——否则浏览器会把页面导航到被放置的文件——在没有任何东西接受时会直接说明。

- 浏览器使用的观察保真度。`scroll text=` 像 `read` 和 `expect` 一样搜索框架和 shadow root，在它们之间选定一个匹配，并且不再滚动到已折叠的元素。`expect.text` 在行内规范化空格但保留换行，因此带缩进的标记可以匹配，而两个独立的块绝不会合并成一句话。控制台诊断会保留页面记录的内容：对象参数以可读的预览到达而不是空消息，条目会指明读者会打开的脚本和行号，未捕获的裸 `throw` 带有其位置。快照会标记 `aria-hidden`，失败的原生 `select` 会列出它确实找到的选项，`aria-labelledby` 可在 shadow root 内解析。

- 浏览器使用会统计它放不下的诊断信息。页面报告显示最新的三条控制台错误和网络失败，读起来就像事情的全部：十二个失败只显示为三个。每当列表被截断，报告现在会指出总数，并指向 `console` 或 `network`。

- 浏览器使用会承认页面摘录提前结束。快照中的可见文本有上限，而报告只说“condensed”，因此长文章读起来仿佛摘录就是整个页面。两条快照路径——无障碍捕获和 DOM 回退——现在都会标记被截断的摘录，并且报告会指明它包含多少内容，并说明页面还有更多。

- 附件报告的是它们实际生成的图像尺寸。把图像调整到视觉补丁预算时会逐条裁剪边缘，这可能要求一个图片并未铺满的框；于是生成的版本比旁边报告的尺寸更小，通过该尺寸映射的坐标也就偏了。现在调整大小会报告生成图像的尺寸。

- 浏览器使用会说明页面脚本在哪里失败。`evaluate` 只保留浏览器错误的第一行，因此多行脚本只报告 `TypeError: ...`，没有任何东西可用来定位。现在失败会携带最内层的堆栈帧，集成测试平台会固定住后面某行 throw 所报告的位置。

- 浏览器使用会指明 PDF，而不是报告一个空页面。打开 PDF 链接会提交地址，但 guest 没有查看它的查看器，因此快照显示的是没有标题、没有文本的页面，以及关于被阻止的查看器样式表的控制台噪音——没有任何东西说明发生了什么。页面报告现在会说明该文档是此浏览器无法显示的 PDF，需要从其 URL 读取文件，并且 Chromium 自带组件为其 `chrome-extension://` 资源引发的失败不再显示为页面的控制台或网络错误。集成测试平台涵盖了导航、安静的报告，以及之后对该页面的快照。

- 浏览器使用不再让 `close_tab` 被可见标签页弹回。`list_tabs` 以普通页面 id 打印可见页面，因此用 `close_tab` 指向它时得到的是 `unknown background tab "p12"; call list_tabs`——而发出该 id 的正是这个列表。现在拒绝信息会说明该页面属于浏览器面板，并建议将其导航到别处或使用 `hide`，不相关的名称仍会报告未知的后台标签页。

- 浏览器使用会说明离开确认实际做了什么。保护未保存工作的页面会用 `beforeunload` 对话框阻止导航，回复要求使用 `handle_dialog`——但 Chromium 自己应答该确认，所以调用总是返回“no JavaScript dialog is currently open”，而重复导航又重复同样的指示。现在回复会说明导航已被放弃、页面保持原状、已没有什么可应答的，而页面中保存的工作必须先完成或丢弃；集成测试平台涵盖了整个流程，包括保护消失后导航顺利通过。

- 浏览器使用的区域设置模拟会到达服务器。`emulate locale` 过去只设置 `navigator.language`，因此页面仍在请求旧语言，站点协商出的内容与模拟相矛盾；现在它也会把区域设置作为 `Accept-Language` 携带，清除它则会恢复浏览器自己的协商。

- 计算机使用的 `capture` 去掉了 `quality`、`maxWidth` 和 `max_ocr_words` 旋钮：改用宿主调校好的默认值（JPEG 质量、缩小宽度，以及元素预算本已限定的 OCR 词数上限），看不清的细节通过 `zoom` 而不是重新编码解决。元素过滤器（`query`、`role`、`visible_only`、`include_noninteractive`、`continuation`）和 `window` 移动几何现在会说明它们的作用，而不是不加解释地留在 schema 里。

- 浏览器使用和计算机使用在模型做决定的地方说明自己在工具阶梯中的位置。`browser` 描述以“last resort: prefer web_fetch, an MCP tool, or a CLI in shell”开头，`computer` 以“last resort after an MCP tool, shell/CLI, and Browser Use; never a stand-in for a page action browser refused”开头，共享规则和两个技能也带有同样的阶梯，因此有 API 或 CLI 的服务会通过它们访问，而不是通过屏幕。两个描述都没有变长：阶梯取代了技能本已负责的措辞。

- 浏览器使用拆为两个工具。`browser` 保留日常页面操作——navigate、snapshot、read、click、fill、表单、对话框、标签页、下载、控制台和网络读取——而开发者控件 `emulate`、`cookies`、`storage`、`intercept`、`init_script` 和 `performance` 移到延迟加载的 `browser_devtools` 工具，它驱动相同的页面和登录，并在首次调用时加载其 schema。日常 schema 去掉了仅由这些操作使用的 33 个字段（cookie 属性、地理位置、CPU 节流、拦截正文、跟踪选项），每个工具的字段说明只列出自己的操作，调用到错误工具时会被拒绝并告知应调用的工具。宿主、其操作注册表、批准策略和集成测试平台保持单一的共享操作契约。

- 内置工具 schema 只陈述契约。`office`、`computer`、`media` 和 `setup` 工具的描述与字段说明去掉了其技能本已负责的方法和策略语句——批处理、何时 snapshot 或 `describe`、在同一回合修复审计、`design.content` 复用、宏处理、不要重新排列、屏幕内容绝不授权操作、视频轮询、删除批准流程——每个回合发送的工具界面因此减少约 2.2 KB（office −878 B，computer −492 B，media −432 B，setup −424 B）。pptx、xlsx 和 pdf 技能现在承载此前只存在于 schema 中的规则（一批已知操作、仅对未知字段使用 `describe`、不可信的文档内容），computer-use 技能则只陈述一次调用契约，而不是重复每一句 schema 语句。

- 浏览器使用每个任务所需的调用更少。`click`、`fill`、`type`、`select`、`hover`、`upload` 和 `scroll`——以及每个 `fill.fields` 条目和 `sequence` 步骤——接受免快照的 `target`（`{role, name}`、`{name}` 或 `{selector}`）来代替 `ref`：宿主自行观察页面，仅在恰好一个匹配时才执行操作（多个子串匹配会解析为唯一一个逐字匹配），含糊的 target 会失败并附上候选项及其新 ref。`snapshot`、`read` 和 `wait` 上的 `query` 以 OR 匹配以空格分隔的关键词（匹配全部关键词的排在最前），并接受 `/pattern/i` 正则表达式，什么也没匹配到的过滤器会说明它过滤了多少元素或字符。透明或 pointer-events:none 的控件不再被直接拒绝：隐藏的复选框会通过其标签被点击，输入目标保护也接受标签的激活。对 `contenteditable` 编辑器的 `fill` 以全选之上的键入输入替换内容，而不是覆盖其 DOM。当某个手势没有改变文档、URL 和控件值时，回复会注明“No observable change”，`brief:true` 只列出自上一次观察以来新增或更改的元素，控制台错误在新出现时只报告一次，已经成立的后置条件是警告而不是错误。快照用 `file-input`、`accept=…` 和 `multiple` 标记文件输入；全页截图在捕获时把固定和粘性元素锚定在文档流中；会话 cookie 用操作系统钥匙串加密存储并在启动时恢复，因此登录在应用重启后得以保留。

- 提示输入框上方的界面元素——Goal 胶囊、运行时进度、工具批准、草稿上下文栏和回合审阅槽——现在位于同一个 `ComposerDock` 中，当这些元素收起时对话记录不再上下晃动：在某个范围的第一次权威 worker 读取进行期间，审阅槽保持预留，因此在对话记录显示之后才到达的 diff 会填入现有的几何空间，而不是再次调整视口大小。腾出的空间绝不靠计时器保留。桌面宿主也不再在每个被接受的提示之后重新读取整个会话（守护进程日志中的“missing baseline”恢复）：重复投影已持有的修订号的回复或通道帧是已应用的状态，而不是交叉的基线。Goal 胶囊的挂载/卸载翻转可在 `MIXDOG_DESKTOP_PERF=1` 下追溯。

- Goal 胶囊不再自行弹出又消失。有两条发布路径造成了闪烁：2 秒的路由脉冲读取原始 Goal 记录，而已完成 Goal 的用户输入归档仍在写入，于是已退役的胶囊又回来了一帧；在 Windows 上，落在原子文件替换内部的 Goal 读取（`EPERM`/`EACCES`/`EBUSY`，或运行时自己正在进行的写入）在那一帧表现为“没有 Goal”。路由发布现在通过 goal-continuation 归档遮罩读取 Goal，Goal 存储则用最后一次提交的记录回答此类读取。

- 浏览器使用不再停下来等待批准：保护 `upload` 以及共享 cookie/localStorage `clear` 的桌面“仅允许一次”对话框已移除，`confirm` 字段离开了浏览器工具契约，browser-use 技能去掉了其对话内的放行规则。`MIXDOG_BROWSER_CONFIRM_ACTIONS` 和 `MIXDOG_BROWSER_DENY_ACTIONS` 仍是确认或拒绝指定操作的唯一方式。

- 窗格阅读栏——输入框、对话记录和 Studio 停靠面板——不再等到窗格达到 1536px 才变宽：从 768px 起它保持 800px，直到窗格超过 1000px，然后按窗格的 80% 跟随，直至 1250px 的 1000px 上限，因此 1536/1680 的窗口以及打开侧边面板的 1920 窗口不再停在 800px，分隔条跨越台阶时也不再让阅读栏猛跳 200px。

- 会话面板以两个固定的启动行 `New task` 和 `New Studio` 开头，固定在会话列表上方。因此 Studio 离开了活动栏：其仅作启动用的栏条目，以及侧视图布局、窗格停靠面板和停靠开关中的启动器例外都已退役，已存储的栏布局在加载时会丢弃 `studio` id。

- 活动栏的“工作流”目的地并入项目面板：`Project | Workflow` 工具栏——即扩展面板的分区开关，现在作为一个 `SidebarSectionToolbar` 组件共享——在项目列表与工作流包、默认代理和代理定义之间切换；标题处的 `+` 跟随项目标签页；`/workflow` 和 `/websearch` 打开工作流标签页；已存储的栏布局在加载时会丢弃已退役的 `workflows` 视图。

- pptx 技能的套件增加了仿照基于令牌的设计系统的设计词汇：`palette()` 推导出三种线条强度（`lineSubtle`、`line`、`lineStrong`）和四种状态色（`T.state.positive | warning | critical | informative`，各有 `solid` / `weak` / `text`，保证对比度并保持在审阅者的饱和度区间之下，因此结论列永远不会触发 `accent_hue_overuse`）；每个距离都落在同一个间距阶梯（`SPACE`）上，并按关系命名（`GAP.bind` / `within` / `between`、`GUTTER`、`PAD`、`M`）；每个文本角色带有固定的行距；重复出现的载体（徽章、标注、箭头序列、统计、表格）从 `SPEC` 读取其结构，带有 `tone` 变体、`stat` 的比例步长和 `statBand()` 辅助函数；图标映射到四个尺寸档；新的 `references/writing.md` 固定了句子、语体、数字、日期、金额、单位和翻译余量的规则，并从 docx 和 xlsx 技能链接。每个规格载体都会为自己的形状签名，构图回执会读回这些签名（`slides[].specs`、`deck.specs`：数量、幻灯片、变体、结构），因此在幻灯片之间字号或字体发生漂移的载体会显示为第二种结构。

- Office 设计令牌推导出同样的四种状态色（`positive`、`warning`、`critical`、`informative`，各有 `Weak` 字段和 `Text` 步长，并对照画布、浅色面板和字段做了对比度检查）；docx 和 xlsx 的决策闸门在 positive 和 critical 状态上绘制“发布”和“停止”，而不是字面色调和第二强调色，`compose_document` 章节的 `calloutTone` 会把其标注放在某个状态上。`compose_sheet` 仪表板的打印区域现在跟随决策面板，因此位于画布之外某一列的“停止”闸门不再被渲染页面和导出页面截掉。

- 未发布的同版本发布恢复现在会在发布前把累积的说明并入该版本，而不是把已发布的工作留在 Unreleased 之下。

## v0.9.95 - 2026-08-06

- 一个全机范围的进程拥有每一个实时会话，终端 TUI 和每个桌面窗口都通过 127.0.0.1 的 HTTP+SSE 传输作为视图接入，因此各界面之间无需协商所有者/查看者角色。
- 提交的提示不会再在各界面之间丢失。守护进程视图的提交保留其同步答复，但会一直重试，直到引擎接收（并在守护进程重启后重新投递）；实时共享的提交由所有者确认，在被拒绝或未确认时回退到持久的 spool；队列会丢弃重新投递的提交 id，而不是把消息发布两次。
- 跨客户端编辑：恢复另一个视图已持有的会话时，会采用那个实时引擎，而不是加载第二份副本；引擎帧会扇出到每个视图，引擎只有在最后一个查看者离开时才会结束——因此终端和桌面窗口可以逐回合地共同驱动同一个会话。
