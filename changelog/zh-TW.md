# 更新日誌

重要變更，由新到舊排列。Deploy 流程在 Unreleased 區段為空時會拒絕發佈，並在發佈時為該區段標上發佈版本。

## Unreleased

新增工作樹設定與分支清理功能，將目標任務重構為工作階段待辦清單，並推出可自訂的輸入框樣式。

### 新功能

- **工作樹設定** — 新增 設定 → 工作樹 頁面，提供磁碟用量統計、開啟與刪除操作，以及超過 15 個工作樹或閒置 30 天後的自動清理規則。
- **分支選單工作樹操作** — 在分支選單底部新增 新增分支、新增工作樹 與 清理 操作，支援搜尋反白與安全的清理預覽。
- **工作階段待辦清單** — 新增取代目標任務的工作階段待辦清單，即時顯示代理進度，並在工作階段關閉後保留最後的待辦項目與目標。
- **輸入框樣式** — 在設定中新增 簡潔、標準 與 詳細 輸入框樣式，支援即時預覽、自適應工具列以及回答時的選用確認步驟 (#270, #276)。
- **委派設定** — 新增獨立的 設定 → 委派 頁面以編輯協調指示，並支援在輸出樣式中直接編輯指示及重設為預設值 (#291)。
- **常式執行子代理** — 支援為排程任務與 Webhook 指定使用獨立模型的執行子代理。
- **匯入 Claude Desktop Cowork** — 支援匯入 Claude Desktop Cowork 對話紀錄，加星號的對話排在最前 (#283)。
- **聊天中的路徑連結** — 支援在聊天中點擊開啟電腦上的任意路徑：資料夾在檔案面板中作為新根目錄開啟，可預覽檔案在 Visualize 中開啟 (#277)。
- **手機端圖片手勢** — 在手機端聊天與 Visualize 中支援雙指縮放、平移與按兩下縮放圖片 (#275)。
- **Fast 呼叫用量統計** — 為模型的 Fast 呼叫增設獨立的用量明細列，並提供適合手機螢幕的用量表格 (#288)。
- **工作階段生命週期自動化** — 在閒置期間自動封存無活動滿 7 天的工作階段，並自動刪除已封存滿 90 天的工作階段。
- **側邊欄工作樹分組** — 在側邊欄的父專案資料夾下將關聯的工作樹工作階段集中分組顯示。
- **電腦使用中暫停手機通知** — 當正在主動使用此電腦時，自動暫停向手機推送通知。

### 變更

- 工具活動列現將重複操作合併為帶計數的標籤與任務名稱，例如「工作樹管理 ×4」。
- 在任何位置修改的設定與指示均在下一輪次立即生效，無須重啟工作階段，也不會破壞提示詞快取。
- 網頁搜尋改為直接載入，略過延遲工具呼叫的步驟，加快查詢速度。
- 手機端遠端瀏覽器滑動關閉手勢現僅限於左側邊緣條觸發，避免操作網頁時誤觸關閉。
- 輸入框中的代理權杖用量數值現會在每次模型呼叫後約 1 秒內更新。
- 閒置垃圾回收現會一併清理外部緩衝區記憶體，降低常駐程式的記憶體用量。

### 問題修復

- 透過持久輪次交接與檢查點復原機制，修復了當機或重新啟動後未儲存輪次遺失的問題。
- 修復了拖曳選取文字後放開滑鼠導致桌面版轉譯器當機的問題。
- 透過保持最近對話掛載，修復了切換工作階段時重新建構記錄或重複播放動畫的問題。
- 修復了停滯的目標將閒置時間計入預算、重複發送通知或未經確認覆蓋現有目標的問題。
- 透過請求重新整理權杖修復了連接器登入在 1 小時後過期的問題，並避免在重用已刪除帳號名稱時切換帳號 (#285)。
- 修復了 Windows 上更新外掛模組重新命名資料夾時因 `EPERM` 檔案鎖定錯誤而失敗的問題 (#284)。
- 修復了嵌入清理期間移除了 onnxruntime-node 指令稿導致安裝失敗的問題 (#282)。
- 修復了處理程序異常結束後因孤立 PostgreSQL 鎖定導致記憶體服務啟動卡住的問題 (#278)。
- 透過授予 Chrome 相容的儲存空間存取權限，修復了內建瀏覽器中 reCAPTCHA 與驗證元件無法運作的問題。
- 修復了子代理報告因提醒、排隊輸入或後續錯誤中斷而未能送達 Lead 代理的問題。
- 修復了 Computer Use 在螢幕讀取緩慢時重新啟動輸入主機，以及在短暫輸入間隔中誤報觀察器損毀的問題。
- 修復了記憶搜尋在多語言混合查詢中遺失韓文內容詞的問題，並最佳化了精確詞彙掃描邏輯。
- 修復了配對手機上的網頁連結與串流瀏覽器分頁未能符合行動裝置螢幕或未在 Visualize 中開啟的問題。
- 修復了狹窄視窗下設定顏色列與說明文字重疊的問題，並防止並行修改指示時發生覆蓋 (#287)。

## v1.4.2 - 2026-10-29

改進代理調度架構：新增專門負責探索程式碼的 Explore 代理與強化驗證的 Test Suite 技能，並支援 Vertex AI 以及單一連接器綁定多個帳號。

### 新功能

- **Explore** — 新增選用的唯讀探索代理，Lead 可一次將多個程式碼問題交給它處理；可在 工作流程 → 內建代理 中選擇其模型。
- **Test Suite 技能** — 新增內建技能，用於撰寫、執行、診斷及整理專案測試。
- **Vertex AI** — 新增 Vertex AI 支援，可使用 Gemini、Claude 與開放模型，支援透過服務帳戶金鑰、gcloud 登入或 Express 模式 API 金鑰登入 (#249)。
- **連接器多帳號** — 單一連接器現在可綁定多個帳號；若未特別指定，代理會使用上次用過的帳號。
- **自訂提供者金鑰與標頭** — 支援設定多組 API 金鑰，在額度用盡時自動接手，並可在每次請求附加自訂 HTTP 標頭 (#233, #239)。
- **機器人的連接器工具權限** — 在機器人設定檔中，可針對各連接器的每項工具分別設定 自動、需要核准 或 已停用 (#264)。
- **從畫面上的機器人直接核准** — 畫面上的機器人對話氣泡會直接顯示請求內容，並提供 允許 與 拒絕 按鈕。
- **一次停止所有背景命令** — 新增 `/stop` 以停止工作階段中的所有背景命令，桌面版現在也支援 `/shells` 與 `/mcp login`。

### 變更

- 檢查失敗時，代理現在會修復根本原因，而非重複執行、拉長逾時時間或直接略過。
- 機器人定期簽到與提示詞快取預熱預設改為關閉。
- 桌面版與 CLI 現在會遵循系統代理伺服器設定，桌面版會依位址套用 PAC 指令稿與例外規則，同時維持本機與區域網路（LAN）位址直接連線。
- 工具活動列現在只會在命令執行期間顯示經過時間。
- 當代理因被判定沒有進展而停止時，現在會在 `history/tool-failures.jsonl` 中寫入一筆 `stall_abort` 紀錄，方便回報被誤停的代理。
- Windows 上的 Git 改為直接啟動 `git.exe`，並減少記錄輪次變更時所建立的行程數量，讓對話輪次、復原／重新套用及 git 工具呼叫更快。

### 問題修復

- 修復在 Windows 上停止命令的相關問題：按下 停止、仍然釋放、發生逾時或關閉工作階段後子行程仍繼續執行、背景命令在停止時可能卡住，以及將無關的舊行程誤判為殘留行程 (#259)。現在每個命令都會在獨立的 Windows 工作物件（Job）中執行；設定 `MIXDOG_SHELL_ALLOW_BREAKAWAY=1` 可讓命令在工作物件外啟動行程。
- 修復群組聊天室在額度用盡時，每個機器人都重複顯示「未能回覆」的問題；現在只會停止一次並說明原因。
- 修復工作階段檢視的多項問題：過長或已壓縮的工作階段無法往上捲動回第一則訊息、其他工作階段傳送大型更新時顯示「工作階段無法使用」，以及手機的「工作階段」抽屜開啟了「機器人」頁面而非對話畫面。
- 修復僅以壓縮檔保存的 Codex 對話無法匯入的問題 (#262)。
- 修復服務端遺失 Mixdog 註冊資訊後，連接器登入重複出現 "Unrecognized client_id" 錯誤的問題 (#269)。
- 修復 TUI 中過長的登入 URL 被截斷的問題，並新增 `Ctrl+Y` 快捷鍵以複製連結 (#261)。
- 修復忙碌的 Windows 電腦無法啟動語音輸入，以及設定或工作階段儲存失敗的問題。
- 修復含有中文、日文的表格儲存格超出表格外框的問題。
- 修復 Vertex AI 模型缺少服務層級（Standard、Flex、Priority）選項，以及排隊中的 Flex 請求在一分鐘後被中斷的問題 (#271)。
- 修復單次讀取進度失敗導致活動計時器停止更新，進而誤判代理沒有進展並將其停止的問題。
- 修復 Computer Use 的 `verify` 無視 `timeout_ms` 在 2 秒後即放棄檢查，以及在無法讀取管理員權限視窗文字時無謂等待的問題 (#274)。

## v1.4.1 - 2026-10-27

修復了透過 SSH 登入、PC 存取設定失敗以及代理在 Anthropic 模型上停止運作的問題，並為並排顯示的 Visualize 分頁新增了檢視切換功能。

### 新功能

- **無瀏覽器登入** — 為 ChatGPT 與 Grok 新增了裝置代碼登入功能，在透過 SSH 連線或無顯示器時於 TUI 面板中顯示登入 URL 或代碼 (#242)。
- **Visualize 檢視切換** — 在並排顯示的 Visualize 分頁縮放膠囊中新增了檢視切換功能，可同時顯示兩個窗格或一次僅顯示一個窗格。
- **從對話直接安裝 APK** — 新增了直接在 Android 套件安裝程式中開啟已下載的 APK 而非透過分享面板開啟的功能 (#241)。

### 變更

- 變更了機器人機制，在向其他機器人傳送訊息、讀取或檢查時透過其 bot id 進行存取。
- 變更了側邊欄、未讀圓點與代理啟動機制，在工作階段清單較長時具備更快的回應速度。

### 問題修復

- 修復了在磁碟機根目錄帶有僅繼承權限的 PC 上設定 PC 存取失敗的問題，並顯示核准未能完成的原因 (#251)。
- 修復了 Anthropic 模型上的代理在思考或寫入大檔案時被判定為停滯並中斷的問題 (#248)。
- 修復了自訂 Responses 路由上的代理在首次輸出前被判定為停滯的問題 (#244)。
- 修復了在部分 PC 上 Computer Use、Browser Use 以及登入回呼回報 "bad port" 錯誤而失敗的問題。
- 修復了在備用模型所屬提供者中選取主模型時回報 "duplicate route provider" 錯誤而失敗的問題。
- 修復了自動切換至備用模型時一次性傳送所有 MCP 工具的問題。
- 修復了匯入的 Claude 與 Codex 對話遺失早期歷程記錄、標題或分頁的問題，並將其工具使用記錄顯示為摺疊的活動列 (#245)。
- 修復了孤立的 worktree 殘留以及預設分支被納入託管 worktree 的問題 (#247)。
- 修復了委派工作結束後機器人仍顯示為工作中以及壓縮工作階段遺失完成圓點的問題。
- 修復了在請求中斷或重新啟動後提示詞快取被重新建置的問題。
- 修復了位於回覆末尾的表格或程式碼區塊遺失底邊框以及手機狹窄螢幕上表格儲存格間距遺失的問題。

## v1.4.0 - 2026-10-27

改進了透過手機搭配 Browser Use 與 Computer Use 進行遠端工作的體驗，並精簡了代理 harness 以略過多餘檢查並更快完成工作。

### 新功能

- **遠端 PC 螢幕** — 新增了透過直接 WebRTC 連線從手機檢視並控制 PC 螢幕的功能，並提供特殊按鍵與 PC 端狀態膠囊。
- **PC 存取** — 新增了可從手機存取系統管理員提示、鎖定畫面與 `Ctrl`+`Alt`+`Del` 的選填存取權限，在 Computer Use 設定中或透過您的 Windows 密碼核准一次即可。
- **瀏覽器即時檢視** — 新增了透過 WebRTC 將應用程式內瀏覽器串流至手機的功能，可自動將接管頁面調整符合螢幕大小，並支援直接透過行動鍵盤輸入。
- **通知控制** — 在設定 → 通知下新增了依裝置設定通知、對話靜音、勿擾時段與錯誤通知功能，並在核准通知上提供允許選項 (#221, thanks @dislight1123)。
- **機器人委派工作** — 針對機器人委派的工作，在回覆下方為每個任務新增了一列即時進度，可顯示進度並讓您在對話中回答問題。
- **已儲存的登入資訊** — 新增了使用在設定 → 認證下管理的已儲存登入名稱與一次性代碼自動登入的功能，模型絕不會接觸機密資料。
- **匯入 Chrome 登入資訊** — 新增了將 Chrome 儲存的登入資訊（包含較新的應用程式綁定加密憑證）匯入全新登入頁面的功能，並具備儲存/保持登入開關。
- **透過郵件登入** — 新增了開啟登入連結並從已驗證電子郵件中填入代碼的功能，並記住各網站所使用的識別提供者。
- **在 Chrome 與 Edge 中使用已儲存的登入資訊** — 新增了 Computer Use 將已儲存的登入資訊填入您專屬的 Chrome 或 Edge 中的功能，且不向模型公開憑證。
- **提示詞快取預熱** — 在設定 → 情境下為 Anthropic 模型新增了提示詞快取自動預熱功能，可學習您返回的使用習慣，並在排程執行前預先預熱機器人。
- **更多 Google 連線** — 新增了將更多 Google 帳戶連線至 Gmail、Calendar 與 Drive 的功能，支援針對每次請求選擇帳戶並提供明確的登入提示。

### 變更

- 變更了代理機制，在完成所有編輯後才進行單次驗證而非於任務中途驗證、同時執行彼此獨立的工具呼叫，並保持簡短的進度更新。
- 將設定重新規劃為四個區塊：基本、AI 行為、整合與支援。
- 變更了工作階段選單，讓您自訂要在側邊欄中顯示哪些區塊。
- 變更了打字、工作階段與分頁切換、搜尋、設定、側邊面板、終端機與變更介面的回應，使其瞬間開啟，並具備更流暢的狀態動畫。
- 變更了機器人委派工作階段的核准機制，使其顯示在等待該核准的每個對話中，並在每張核准資訊卡上維持相同的文字與按鍵。
- 變更了工作階段與機器人列，在等待核准時顯示琥珀色三角形，遇到提問時顯示問號圖示，並展示待處理工作數量。
- 變更了機器人任務工作階段與子代理，使其帶有獨立的未讀圓點，並隨回報對象對話一起標示為已讀。
- 變更了已配對手機的處理方式，使其能如同 PC 端一般讀取、預覽、下載與開啟檔案。
- 變更了 `@` 檔案選取器，優先列出層級較淺的路徑，預設開啟近期工作，並能在連結資料夾中尋找檔案 (#228, thanks @reeves-ai-lch)。
- 變更了 Visualize，可從任何本機資料夾開啟頁面，並以所屬資料夾命名索引頁面。
- 變更了用量快顯視窗與已固定的用量指示列，在全寬進度列上方以單行顯示各項額度上限。
- 變更了 shell 工具，使其可接收選填的工作目錄，並拒絕 2 秒或更長時間的 sleep。
- 變更了代理終端機執行與瀏覽器頁面，使其在 PC 及配對裝置上顯示對應分頁，並可直接從對話記錄行開啟。
- 變更了 Browser Use，限制每個工作階段的背景頁面數量，並在單輪互動結束後將其關閉。
- 變更了重試等待畫面，顯示固定的原因與即時倒數計時，而非未處理的錯誤文字。
- 變更了機器人對話，回覆下方不再顯示變更檔案資訊卡、分隔時間相隔較遠的訊息，並以單行共用顯示交接與時間。
- 變更了語言清單，將韓文以其母語名稱顯示。
- 變更了 Mixy 的定期檢查機制，預設每小時執行一次，可在設定 → 機器人中選擇間隔。
- 變更了手機應用程式，使其在網路允許時直接連線至 PC，並自動退回使用中繼。
- 變更了側邊面板使其共用同一寬度，可在 280 到 1160 像素之間調整。
- 調整了手機側邊 dock，可透過在面板任意處滑動來關閉，並讓抽屜列與文字微光效果的動畫更加流暢。

### 問題修復

- 修復了應用程式本機儲存空間重設時分割窗格版面配置遺失的問題。

### 新功能

- 對話壓縮後，先前的訊息、工具卡片與 diff 依然保留在 "對話已壓縮" 分隔線上方以供閱讀，而不會直接消失。它們僅供介面顯示（絕不會傳送給模型），重新啟動應用程式後向上捲動即可重新載入，每個工作階段最多佔用約 32 MB（優先清理最早的記錄），與一般歷史記錄一樣過濾敏感資訊，並隨工作階段刪除而清除；接續進行的工作階段會連結至歷史記錄而非重複複製。壓縮前的輪次不提供復原、重新套用與重試功能。

## v0.9.172 - 2026-09-21

- 頁面開啟時不再宣告它從未進行過的下載。已儲存的檔案屬於工作階段，但每個頁面都從零開始追蹤自己回報過的內容，因此之後開啟的每個頁面都會向呼叫者報告整份積壓清單——例如搜尋頁面回報了另一個分頁數分鐘前儲存的檔案。新頁面一開始就知道它存在之前發生的事；它開啟期間儲存的檔案仍會傳達給它。

- 用戶端路由變更會回應它產生的畫面，而不是呼叫者離開的那一個。單頁應用程式以 `history.pushState` 移動網址，並在稍後轉譯新檢視；沒有文件載入，所以穩定偵測看到安靜的頁面就立即返回——而 `expect.url` 也在任何內容繪製之前就被新網址滿足。在 react.dev 上點擊「Learn」，回應的是位於 `/learn` 網址下的首頁。當動作在沒有載入的情況下改變網址時，回覆現在會等待頁面安靜下來，且 URL 條件不得將此等待截短。在真實裝置測試環境中量測：navigate、click 與 snapshot 的延遲沒有改變，因為只有同文件的路由變更才需要額外等待。

- 開啟分頁的點擊不再被回報為什麼都沒做的點擊。`target="_blank"` 連結不會動到目前的文件，因此回覆回答「No observable change」，並叫呼叫者去找遮擋的元素——而它剛開啟的頁面卻在 `list_tabs` 中沒有被提及。回覆現在會指出所開啟的頁面，以及如何對其操作。

- `drag` 和其他所有指標動作一樣，接受免快照的目標。它的兩端以前只接受 ref 或原始座標，而頁面設為可拖曳的元素——卡片、清單列、放置區——往往沒有無障礙名稱，因此也沒有 ref，所以即使已知 CSS 選擇器，移動一個元素也得先做視覺快照定位。現在 `target` 與 `dropTarget` 命名兩端，並在同一次觀察中一併解析；ref 與座標仍照常運作，且兩端仍必須以相同方式指定。

- 瀏覽器使用 元素截圖。`snapshot mode=visual` 接受 `ref` 或 `target`，並將該元素作為獨立圖片回傳。方框以頂層文件的 CSS 像素量測——同處理程序框架在頁面端折入其偏移量，跨來源框架加入其工作階段偏移量，但不做保護輸入的點擊測試，因為圖片不會派發任何事件，而處於 CSS 轉換下的框架同樣值得一張圖——裁切則依圖片對視口的比例縮放，因此在縮放或高 DPI 顯示器上也成立。比視窗更高或更寬的元素是從文件擷取而非視口中裁出，因此長表格或文章會完整送達，而不是止於摺疊線；只有大到無法擷取的頁面才會退回可見部分，並會說明。該圖片僅供檢視：絕不會被綁定為座標定位，因為對元素操作的方式仍是 ref。`mode=semantic`、`fullPage` 與 `format=pdf` 會拒絕 target，而不是忽略它。

- 瀏覽器使用 輸入保真度。`drag` 現在能完成頁面自己的 HTML5 拖曳：Chromium 的拖曳攔截交出頁面開始的酬載，手勢以 `dragEnter`/`dragOver`/`drop` 完成，這正是看板卡片、可排序清單或檔案放置區實際監聽的事件；只追蹤滑鼠事件的頁面維持原先的路徑。`type` 為每個字元送出真實的按鍵事件，而不是插入整個字串，因此由按鍵驅動的自動完成與組合方塊會有反應，而美式鍵盤配置以外的字元（韓文、emoji）仍以文字插入。`press` 為標點符號送出美式按鍵碼（`.` 過去是 Delete，`-` 過去是 Insert），避免快速鍵輸入字元，也不再從大寫字母推斷 Shift，這曾使 `Control+A` 變成 `Control+Shift+A`。`upload` 會把檔案放到從不開啟檔案選擇器的元素上，並帶有中和未處理放置的防護——否則瀏覽器會把頁面導覽到被放下的檔案——且在沒有任何元素接受時會清楚回報。

- 瀏覽器使用 觀察保真度。`scroll text=` 像 `read` 與 `expect` 一樣搜尋框架與 shadow root，在其間選出一個相符項，且不再捲動到已收合的元素。`expect.text` 會正規化行內的空格但保留換行，因此縮排的標記可以相符，而兩個獨立區塊也絕不會併成一句。主控台診斷會保留頁面記錄的內容：物件引數以可讀的預覽呈現而不是空訊息，項目會指出讀者會開啟的指令碼與行號，未捕捉的單純 `throw` 也帶有其位置。快照會標記 `aria-hidden`，失敗的原生 `select` 會列出它確實找到的選項，`aria-labelledby` 也能在 shadow root 內解析。

- 瀏覽器使用 會計算它放不下的診斷。頁面報告顯示最新的三筆主控台錯誤與網路失敗，讀起來像是全部：十二個失敗只顯示為三個。報告現在會指出總數，並在清單被截斷時指向 `console` 或 `network`。

- 瀏覽器使用 會承認頁面摘錄提早結束。快照中的可見文字有上限，而報告只說「condensed」，因此長文章讀起來彷彿摘錄就是整個頁面。兩條快照路徑——無障礙擷取與 DOM 後備——現在都會標記被截斷的摘錄，報告會指出它帶有多少內容，並說明頁面還有更多。

- 附件會回報它們實際產生的圖片大小。為符合視覺補丁預算而調整圖片大小，會一次修剪一邊，這可能要求一個圖片填不滿的方框；產生的版本因此比旁邊回報的大小更小，透過該大小對應的座標也就偏了。調整大小現在會回報所產生圖片的尺寸。

- 瀏覽器使用 會指出頁面指令碼在哪裡失敗。`evaluate` 只保留瀏覽器錯誤的第一行，因此多行指令碼回報 `TypeError: ...` 卻無從定位。失敗現在會附帶最內層的堆疊框架，整合測試環境也固定了後面某行的 throw 所回報的位置。

- 瀏覽器使用 會指名 PDF，而不是回報空白頁面。開啟 PDF 的連結會提交網址，但 guest 沒有檢視器，因此快照顯示一個無標題、無文字的頁面，以及關於被封鎖的檢視器樣式表的主控台雜訊——沒有任何內容說明發生了什麼。頁面報告現在會說明該文件是此瀏覽器無法顯示的 PDF，必須從其 URL 讀取檔案；Chromium 自己內建元件為其 `chrome-extension://` 資源引發的失敗，也不再顯示為頁面的主控台或網路錯誤。整合測試環境涵蓋了導覽、安靜的報告，以及之後對該頁面的快照。

- 瀏覽器使用 不再讓 `close_tab` 在可見分頁上碰壁。`list_tabs` 以一般頁面 id 列印可見頁面，因此把 `close_tab` 指向它時，得到的是 `unknown background tab "p12"; call list_tabs`——也就是交出這個 id 的那份清單。拒絕訊息現在會說明該頁面屬於瀏覽器面板，並指向將其導覽至他處或 `hide`，而無關的名稱仍會回報未知的背景分頁。

- 瀏覽器使用 會說明離開確認實際做了什麼。保護未儲存工作的頁面以 `beforeunload` 對話框擋下導覽，而回覆要求使用 `handle_dialog`——但 Chromium 會自行回應該確認，因此該呼叫總是回傳「no JavaScript dialog is currently open」，重複導覽也只是重複同一個指示。回覆現在會說明導覽已被放棄、頁面留在原處、已沒有可回應的內容，以及頁面中的工作必須先完成或捨棄；整合測試環境涵蓋整個序列，包括防護消失後導覽順利通過。

- 瀏覽器使用 的地區設定模擬會到達伺服器。`emulate locale` 過去只設定 `navigator.language`，因此頁面仍請求舊語言，網站協商出與模擬相矛盾的內容；現在它也將該地區設定作為 `Accept-Language` 帶出，清除後會還原瀏覽器本身的協商。
